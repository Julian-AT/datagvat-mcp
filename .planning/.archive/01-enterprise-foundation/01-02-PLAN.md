<task type="auto">
  <name>Task 2: Standardize error handling with ToolError</name>
  <files>app/tools/analysis.py, app/tools/discovery.py, app/tools/management.py, app/tools/vocabularies.py</files>
  <action>
For each tool with error handling issues identified in Task 1:

1. **Import ToolError** if not already imported:
   ```python
   from fastmcp.exceptions import ToolError
   ```

2. **Replace error returns with ToolError raises:**
   - Before: `return {"error": "Dataset not found"}`
   - After: `raise ToolError("Dataset not found")`

3. **Wrap client exceptions with context:**
   - Before: `except Exception as e: return {"error": str(e)}`
   - After: `except PiveauApiError as e: raise ToolError(f"Failed to fetch dataset: {e}") from e`

4. **Preserve successful returns unchanged** - only modify error paths.

Why ToolError: FastMCP's ErrorHandlingMiddleware (added in Plan 01) automatically wraps ToolError in `{"isError": true, "content": [...]}` format, ensuring consistent error format across all tools as required by ENTERPRISE-04.

Do NOT change exception types raised by PiveauClient - those are already well-defined (PiveauApiError, PiveauNotFoundError, PiveauAuthError). Only standardize how tools expose those errors to MCP clients.
  </action>

- grep -r "ToolError" app/tools/ shows ToolError used consistently
- All tools import ToolError from fastmcp.exceptions
- python -m pytest tests/test_tools/ passes (if tests exist)
  </verify>
  <done>All tools use ToolError for business failures, consistent error format achieved</done>

<task type="auto">
  <name>Task 3: Add progress reporting to long-running tools</name>
  <files>app/tools/analysis.py, app/tools/discovery.py</files>
  <action>
Identify tools that iterate over multiple items (candidates for progress reporting):
- list_catalogues
- list_datasets (within catalogue)
- search_datasets (when implemented)
- analyze_dataset_quality (if it fetches multiple datasets)

For each qualifying tool, add progress reporting using Context.report_progress():

```python
@mcp.tool
async def list_datasets(catalogue_id: str, limit: int = 100, ctx: Context = None) -> list[dict]:
    datasets = []
    total = limit  # Or fetch count first if API supports it

    async for i, dataset in enumerate(fetch_datasets_iterator()):
        if ctx:
            await ctx.report_progress(
                progress=i,
                total=total,
                message=f"Fetching dataset {i+1}/{total}..."
            )
        datasets.append(dataset)

    if ctx:
        await ctx.report_progress(total, total, "Complete")

    return datasets
```

Key points:
- Only add to tools that process >10 items OR take >2 seconds
- Check `if ctx:` before calling report_progress (ctx is optional)
- Report progress at meaningful intervals (every item, or every N items for large batches)
- Final progress call should be (total, total, "Complete")
- Do NOT add to single-item fetch tools (get_dataset, get_catalogue)

Why: Satisfies ENTERPRISE-06 requirement for progress visibility on long operations.
