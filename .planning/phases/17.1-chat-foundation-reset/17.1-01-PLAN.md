Analyze key files and document patterns:
- `lib/db/schema.ts` - Their chat/message schema with parts array
- `app/(chat)/api/chat/route.ts` - Stream creation, immediate persistence, onFinish pattern
- `app/(chat)/api/files/upload/route.ts` - File upload to Vercel Blob before message send
- `components/message.tsx` - Parts-based rendering (map through parts array)
- `components/multimodal-input.tsx` - Upload-first pattern in action

Compare with our current implementation:
- Our schema already has parts array (good!) but missing GIN index for querying
- Our chat route uses experimental_transform (their pattern: data stream annotations)
- Our approach: cache visualizations, upload in onFinish (their pattern: upload immediately in tool execute)
- Both use same MessagePart union structure - we just need to ensure visualization type supported

Key insights to document:
1. **Upload-first**: Files uploaded BEFORE message sent, message only contains URLs
2. **Immediate persistence**: User message saved BEFORE streaming starts (not just in onFinish)
3. **No experimental_transform**: Use data stream annotations for custom events instead
4. **Parts rendering**: Map through parts array, render different component per type
