<task type="auto">
  <name>Implement configuration writers for each tool</name>
  <files>
    packages/cli/src/configure.ts
    packages/cli/src/templates.ts
  </files>
  <action>
    Create configuration file manipulation logic:

    **src/templates.ts:**
    - Export function getMcpConfig(): object
    - Return: { command: "npx", args: ["-y", "@datagvat/mcp-server"] }
    - This is the MCP server config that gets added to each tool

    **src/configure.ts:**
    - Import fs (promises), path
    - Import getMcpConfig from './templates.ts'
    - Import UI helpers from './ui.ts'
    - Import ToolInfo type from './types.ts'
    - Export async function configureTools(tools: ToolInfo[]): Promise<void>
    - For each tool:
      1. Check if config file exists
      2. If exists: Read and parse JSON
      3. If not exists: Create parent directory (fs.mkdir recursive), use empty config
      4. Check if 'datagvat' key already exists in mcpServers
      5. If exists: Skip with warning (already configured)
      6. Else: Merge mcpServers with { datagvat: getMcpConfig() }
      7. Write back to config file with JSON.stringify(config, null, 2)
      8. Show success message with file path
    - Handle errors per tool (continue to next tool if one fails)
    - Tool-specific config structure:
      - Claude Desktop: { mcpServers: { ... } }
      - Continue: { mcpServers: { ... } }
      - Cline: { mcpServers: { ... } }
    - Return summary: { configured: number, skipped: number, failed: number }

    Error handling:
    - Invalid JSON: Show warning, create new config file with MCP server only
    - Permission denied: Show error with actionable message (run as admin, check permissions)
    - Missing parent directory: Auto-create with fs.mkdir({ recursive: true })

    Use fs.promises for async operations, catch errors per tool to continue batch
  </action>
  <verify>

    Check that existing mcpServers are preserved (merge, not replace)
    Verify 'datagvat' key is added correctly
    Test error cases: invalid JSON, missing directory, already configured
  </verify>
  <done>

    Existing config is preserved (merge strategy)
    Already-configured tools are skipped with warning message

    Invalid JSON is handled gracefully with new config creation
  </done>
