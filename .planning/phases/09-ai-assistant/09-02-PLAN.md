  <action>
Create `docs/app/api/chat/route.ts` implementing the streaming chat API from research (Pattern 2: API Route with streamText).

Route structure:
```typescript
import { streamText, tool, convertToModelMessages } from 'ai';
import { openaiCompatible } from '@ai-sdk/openai-compatible';
import { mcpClient } from '@/lib/mcp/client';
import { convertMCPTools } from '@/lib/mcp/tools';

export const maxDuration = 30; // Vercel function timeout

export async function POST(req: Request) { ... }
```

Implementation requirements:

1. **Rate limiting** (top of POST handler):
   - Use simple Map-based rate limiter (research Pitfall 6 pattern)
   - Limit: 5 requests per minute per IP
   - Extract IP from x-forwarded-for header or 'unknown'
   - Return 429 status with clear message if exceeded

2. **Request parsing**:
   - Parse JSON body to extract messages array
   - Validate messages array exists (return 400 if missing)

3. **MCP tool loading**:
   - Call mcpClient.listTools() to get MCP tools dynamically
   - Call convertMCPTools(mcpTools) to get AI SDK format
   - Handle empty tools array gracefully (chat still works, just no tools)

4. **Model configuration**:
   - Use openaiCompatible provider with Claude model
   - Model: 'claude-3-5-sonnet-20241022'
   - BaseURL: process.env.ANTHROPIC_BASE_URL || 'https://api.anthropic.com/v1'
   - API key: process.env.ANTHROPIC_API_KEY (required)
   - Check API key exists, return 500 with "ANTHROPIC_API_KEY not configured" if missing

5. **Streaming setup**:
   - Call streamText with:
     - model configuration
     - system: "You are a helpful assistant for exploring Austrian open data from data.gv.at. Use the available tools to search and retrieve dataset information."
     - messages: convertToModelMessages(messages)
     - tools: converted MCP tools object
     - maxSteps: 5 (allow multi-step tool calling)
     - onFinish: Log completion with finishReason and token usage

6. **Response**:
   - Return result.toUIMessageStreamResponse()
   - Include sendReasoning: true option
   - Include onError callback that logs and returns user-friendly message

7. **Error handling**:
   - Wrap entire handler in try/catch
   - Log errors with [Chat] prefix
   - Return 500 with JSON error on failure
   - DO NOT throw errors that break stream

AVOID:
- Reading stream body before returning (Pitfall 2 - body consumed)
- Synchronous tool execution (Pitfall 3 - blocking streaming)
- Missing error handling (Pitfall 5 - cryptic failures)
- Forgetting maxDuration (Pitfall 4 - 10s timeout)

Follow research "API Route with MCP Tool Integration" code example structure closely.
