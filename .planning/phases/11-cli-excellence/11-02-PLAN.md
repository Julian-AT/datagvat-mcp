Create diff.ts module for displaying configuration changes:

**Export generateDiff(oldContent: string, newContent: string):**
- Use jsdiff's `diffLines` to compute line-level differences
- Return array of Change objects from jsdiff

**Export displayDiff(diff: Change[]):**
- Iterate through diff array
- Color added lines green with "+ " prefix
- Color removed lines red with "- " prefix
- Color unchanged lines dim gray with "  " prefix
- Use chalk from existing ui.ts patterns
- Print with console.log for each line
- Add empty line before and after diff block for spacing

**Export previewConfigUpdate(oldConfig: string, newConfig: string): Promise<boolean>:**
- Generate diff using generateDiff
- Display header: chalk.bold('Configuration changes:')
- Display diff using displayDiff
- Use @inquirer/prompts confirm() to ask: "Apply these changes?"
- Default to true
- Return user's confirmation

Handle edge cases:
- Empty diff (no changes): Display "No changes detected" and return false
- Very large diffs (>50 lines): Show line count warning before displaying
- Non-TTY environment: Skip preview, log "Non-interactive mode: applying changes" and return true if --yes flag present

Import types from jsdiff: `import { diffLines, type Change } from 'diff';`
Follow existing ui patterns for chalk usage and console formatting.

Create update.ts command for updating MCP server configuration:

**Command signature:**
```typescript
interface UpdateCommandOptions {
  yes?: boolean;      // Skip diff preview confirmation
  tool?: string;      // Update specific tool only
}

export async function updateCommand(options: UpdateCommandOptions): Promise<void>
```

**Implementation flow:**

1. **Display header:** ui.header('Update Configuration', 'Update data.gv.at MCP Server configuration')

2. **Detect current state:**
   - Call detectTools() to find configured tools
   - Filter to tools where tool.detected && tool.configured
   - If no configured tools, show error: "No configured tools found. Run 'datagvat-mcp init' first."

3. **Select tools to update:**
   - If options.tool specified: find that tool or error
   - If options.yes: use all configured tools
   - Otherwise: use checkbox prompt (similar to init command)

4. **For each tool:**
   - Read current config file (use tool.configPath)
   - Generate new config (use configureTools logic but don't write yet)
   - Compare configs using previewConfigUpdate
   - If user approves (or --yes flag), write new config
   - Track updated/skipped/failed counts

5. **Display summary:**
   - ui.success(`Updated ${count} tool(s)`)
   - If any failed: ui.error with specific tool names

6. **Error handling:**
   - Catch file read errors: "Failed to read config at {path}"
   - Catch file write errors: "Failed to write config at {path}"
   - Use formatError from ui module
   - Handle ExitPromptError (Ctrl+C)

**CI mode handling:**
- Check isCI() and require --yes flag if in CI
- Use requireNonInteractive() from ci module

Create doctor.ts command for health check diagnostics:

**Command signature:**
```typescript
interface DoctorCommandOptions {
  fix?: boolean;  // Attempt automatic fixes (future: for now, just show fix instructions)
}

export async function doctorCommand(options: DoctorCommandOptions): Promise<void>
```

**Health checks (define as array of check objects):**

1. **Config files exist:**
   - Check each tool's config path (from detectTools)
   - OK if file exists, FAIL if missing
   - Fix: "Run: datagvat-mcp init"

2. **Config files are valid JSON:**
   - Read and parse each config file
   - OK if JSON.parse succeeds, FAIL on syntax error
   - Fix: "Manually fix JSON syntax or run: datagvat-mcp init --tool {name}"

3. **MCP server entry exists:**
   - Check config has mcpServers (or servers) key
   - Check key contains 'data-gv-at' entry
   - OK if exists, FAIL if missing
   - Fix: "Run: datagvat-mcp init --tool {name}"

4. **MCP server path is valid:**
   - Extract command path from MCP server config
   - Check if file exists at that path
   - OK if file exists, WARN if missing
   - Fix: "Update path in config or reinstall MCP server"

5. **Node.js is available:**
   - Use execa to run: `node --version`
   - OK if succeeds, FAIL if error
   - Fix: "Install Node.js 18+ from https://nodejs.org"

6. **Python is available (for MCP server):**
   - Use execa to run: `python --version` or `python3 --version`
   - OK if succeeds, WARN if error
   - Fix: "Install Python 3.11+ for MCP server"

7. **uv is available (recommended):**
   - Use execa to run: `uv --version`
   - OK if succeeds, INFO if missing (optional)
   - Fix: "Install uv: curl -LsSf https://astral.sh/uv/install.sh | sh"

**Implementation pattern:**
```typescript
interface HealthCheck {
  name: string;
  severity: 'error' | 'warning' | 'info';
  check: () => Promise<{
    ok: boolean;
    message: string;
    fix?: string;
  }>;
}

const checks: HealthCheck[] = [
  {
    name: 'Config files exist',
    severity: 'error',
    check: async () => {
      // implementation
    }
  },
  // ... more checks
];
```

**Execution flow:**
1. Display header: ui.header('Health Check', 'Diagnose data.gv.at MCP Server configuration')
2. Show: "Running {checks.length} health checks..."
3. For each check:
   - Start ora spinner with check name
   - Run check function
   - If ok: spinner.succeed(green message)
   - If not ok: spinner.fail(red message) or spinner.warn(yellow message) based on severity
   - If fix available: console.log(chalk.yellow('  → Fix: ') + fix)
4. Display summary:
   - If all passed: ui.success('All checks passed') and exit(0)
   - If any failed: ui.error(`${count} issue(s) found`) and exit(1)
   - If warnings only: ui.warning(`${count} warning(s)`) and exit(0)

**Integration with index.ts:**
Add command after 'update':
```typescript
program
  .command('doctor')
  .description('Check configuration health and diagnose issues')
  .option('--fix', 'attempt automatic fixes (show instructions)')
  .action(doctorCommand);
```

Import: `import { doctorCommand } from './commands/doctor.js';`

Use execa for shell commands: `import { execa } from 'execa';`
Handle execa errors gracefully (command not found should be caught, not crash).

Follow existing patterns for error handling and UI consistency.
