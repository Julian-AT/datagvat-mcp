   ```python
   from typing import Annotated

   dataset_id: Annotated[str, StringConstraints(min_length=1, max_length=200)]
   ```

   ```python
   limit: Annotated[int, Field(ge=1, le=1000)] = 100
   offset: Annotated[int, Field(ge=0)] = 0
   ```

   from app.models import ValueType

   api_key: Annotated[str | None, StringConstraints(min_length=10)] = None

- Pagination (limit, offset): limit 1-1000, offset >= 0

- Do NOT add regex validation for IDs (Piveau format is flexible)
- Do NOT validate URL formats for external URLs (Piveau handles this)
- Do NOT add custom validators unless strictly necessary

<task type="auto">
  <name>Task 2: Implement graceful degradation in PiveauClient</name>
  <files>app/client.py</files>
  <action>
Enhance PiveauClient._request() method to handle API unavailability gracefully:

**Current behavior:** Exceptions bubble up, tools fail completely.

**Target behavior:**
1. **Connection errors** - API unreachable (network down, DNS failure):
   - Catch: httpx.ConnectError, httpx.TimeoutException
   - Raise: ToolError with clear message + suggestion to check API status
   - Log: Warning level with correlation ID

2. **5xx errors** - API available but failing:
   - Already handled via httpx.Response.raise_for_status()
   - Let RetryMiddleware (from Plan 01) handle retries
   - After max retries exhausted, raise ToolError with server error context

3. **Graceful degradation for optional operations:**
   - For analyze_dataset_quality: if DQV metrics endpoint fails, return partial results
   - For list_vocabularies: if vocab endpoint fails, return cached/default values
   - For mandatory operations (get_dataset, list_catalogues): fail fast with clear error

**Implementation pattern:**
```python
async def _request(self, method: str, path: str, **kwargs) -> httpx.Response:
    try:
        response = await self._client.request(method, url, **kwargs)
        response.raise_for_status()
        return response
    except (httpx.ConnectError, httpx.TimeoutException) as e:
        # API unreachable
        raise ToolError(
            f"Piveau API unavailable at {self._base_url}: {e}. "
            "Check network connection and API status at https://qs.data.gv.at/status"
        ) from e
    except httpx.HTTPStatusError as e:
        if e.response.status_code >= 500:
            # Server error - RetryMiddleware already tried, now fail gracefully
            raise ToolError(
                f"Piveau API server error ({e.response.status_code}): {e.response.text[:200]}"
            ) from e
        # Client errors (4xx) bubble up normally
        raise
```

Why: Satisfies ENTERPRISE-08 requirement. Users get actionable error messages instead of raw exceptions.
  </action>
  <verify>

- Error messages include actionable guidance
- 5xx errors after retry produce clear ToolError
- 4xx errors (auth, not found) still use existing exception types
- python -m pytest tests/test_client.py passes (if tests exist)
  </verify>
  <done>PiveauClient gracefully degrades on API unavailability, clear error messages provided</done>

**Enhancements needed:**
1. Log the degradation (logger.warning) so it's visible in structured logs
2. Include degradation reason in response: `{"quality_score": null, "degraded": true, "reason": "DQV metrics unavailable"}`
3. Still return useful data (dataset exists, has distributions, etc.)

**Pattern to apply:**
```python
result = {"dataset_id": dataset_id, "analysis": {...}}

try:
    dqv_metrics = await client.get_dataset_metrics(dataset_id)
    result["dqv_metrics"] = dqv_metrics
except PiveauApiError as e:
    logger.warning(f"DQV metrics unavailable for {dataset_id}: {e}")
    result["dqv_metrics"] = None
    result["degraded"] = True
    result["degradation_reason"] = "Quality metrics service unavailable"

return result
```

Why: Partial results are better than complete failure. Users can still analyze dataset structure even if quality metrics fail.
