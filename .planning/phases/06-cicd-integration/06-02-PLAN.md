<task type="auto">
  <name>Task 1: Add path filtering action to detect changed files</name>
  <files>.github/workflows/ci.yml</files>
  <action>
Add a new job called `filter` that runs before the existing jobs and uses `dorny/paths-filter@v2` to detect which file categories changed.

**Implementation:**

1. Add `filter` job as the first job in the workflow (after the `jobs:` key)
2. Configure `dorny/paths-filter@v2` with two filters:
   - `docs`: `['docs/**', '.github/workflows/ci.yml']`
   - `python`: `['mcp/**', 'pyproject.toml', 'setup.py']`
3. Output both filter results for use by downstream jobs

**Example structure:**
```yaml
jobs:
  filter:
    runs-on: ubuntu-latest
    outputs:
      docs: ${{ steps.filter.outputs.docs }}
      python: ${{ steps.filter.outputs.python }}
    steps:
      - uses: actions/checkout@v4
      - uses: dorny/paths-filter@v2
        id: filter
        with:
          filters: |
            docs:
              - 'docs/**'
              - '.github/workflows/ci.yml'
            python:
              - 'mcp/**'
              - 'pyproject.toml'
              - 'setup.py'
```

**Why this approach:**
- `dorny/paths-filter@v2` is the standard GitHub Actions action for path-based job filtering
- Creates explicit outputs that downstream jobs can reference
- More maintainable than workflow-level path filters (centralized logic)
</action>

  <files>.github/workflows/ci.yml</files>
  <action>
Modify the `docs` job to only run when documentation files have changed.

**Implementation:**

1. Add `needs: filter` to docs job dependencies
2. Add `if: needs.filter.outputs.docs == 'true'` conditional to docs job
3. Keep all existing steps unchanged (Setup Bun, Install dependencies, Validate, Build, Upload artifacts)

**Example structure:**
```yaml
  docs:
    needs: filter
    if: needs.filter.outputs.docs == 'true'
    runs-on: ubuntu-latest
    steps:
      # existing steps remain unchanged
```

**Why this approach:**
- `needs: filter` ensures filter job runs first and provides outputs
- `if` conditional prevents entire docs job from running when condition is false
- GitHub Actions skips the job entirely (not just the steps), saving CI minutes
</action>

<task type="auto">
  <name>Task 4: Remove workflow-level path filters</name>
  <files>.github/workflows/ci.yml</files>
  <action>
Remove the workflow-level `paths:` filters from both `push` and `pull_request` triggers, since filtering is now handled at the job level.

**Implementation:**

1. In the `on:` section, remove the `paths:` key and its values under `push:` (lines 6-11)
2. Remove the `paths:` key and its values under `pull_request:` (lines 14-19)
3. Keep the `branches:` filters for both triggers

**Before:**
```yaml
on:
  push:
    branches: [ main, develop ]
    paths:
      - 'docs/**'
      - 'mcp/**'
      - '.github/workflows/ci.yml'
      - 'pyproject.toml'
      - 'setup.py'
  pull_request:
    branches: [ main, develop ]
    paths:
      - 'docs/**'
      - 'mcp/**'
      - '.github/workflows/ci.yml'
      - 'pyproject.toml'
      - 'setup.py'
```

**After:**
```yaml
on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]
```

**Why this approach:**
- Workflow-level path filters are too coarse-grained (all-or-nothing)
- Job-level conditionals with dorny/paths-filter provide fine-grained control
- Removing workflow-level filters ensures the workflow always runs (filter job decides which downstream jobs run)
</action>
