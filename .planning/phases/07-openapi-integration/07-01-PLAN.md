<task type="auto">
  <name>Task 1: Create schema download script with validation</name>
  <files>docs/scripts/download-openapi.ts</files>
  <action>
Create download script at docs/scripts/download-openapi.ts that:

1. **Fetches schema from data.gv.at:**
   - URL: https://qs.data.gv.at/api/hub/repo/openapi.yaml
   - Use Bun native fetch (not external libraries)
   - Check response.ok and handle HTTP errors with clear messages

2. **Validates schema structure:**
   - Check YAML contains "openapi:" field
   - Extract and validate version (must be 3.0 or 3.1)
   - Use regex: `/openapi:\s*['"]?(\d+\.\d+)/`
   - Reject if version is not 3.0 or 3.1 (fumadocs-openapi requirement)

3. **Writes schema to disk:**
   - Target: `./data.gv.at-openapi.yaml` (relative to docs/ directory)
   - Use `await Bun.write(OUTPUT_PATH, yaml)`

4. **Provides clear console output:**
   - Use professional format: "Downloading OpenAPI schema...", "✓ Schema downloaded successfully"
   - Include metadata: version, file size in KB
   - Error messages: "✗ Failed to download schema" with reason
   - Exit code 1 on failure for CI integration

5. **Follow existing script conventions:**
   - Match style of docs/scripts/prebuild.ts (seen in context)
   - Wrap in async main() function
   - Use try/catch for error handling
   - Use Bun APIs consistently

**Why Bun fetch:** Project uses Bun as primary runtime (01-01 decision), provides native HTTP without dependencies.

**Why validation:** Corrupted or wrong-version schemas cause cryptic build errors in fumadocs-openapi (RESEARCH.md Pitfall 1).

**Why detailed output:** CI debugging requires clear indication of what failed and why.
