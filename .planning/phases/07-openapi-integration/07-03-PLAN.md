<objective>
Automate weekly OpenAPI schema updates with GitHub Actions and PR creation for safe review.

Purpose: Ensure API documentation stays current with data.gv.at changes through automated weekly updates that create pull requests for review rather than direct commits, preventing breaking changes from reaching production without human verification.

Output: GitHub Actions workflow that runs weekly, downloads latest schema, detects changes, and creates PR if schema updated.
</objective>

  <files>.github/workflows/update-openapi.yml</files>
  <action>
Create GitHub Actions workflow at .github/workflows/update-openapi.yml:

1. **Workflow triggers:**
   - Schedule: `cron: '0 9 * * 1'` (every Monday 09:00 UTC)
   - Manual: `workflow_dispatch` (allows manual trigger for testing)
   - RESEARCH.md Pitfall 6: Scheduled workflows pause after 60 days inactivity - manual trigger ensures testability

2. **Job structure:**
   - Name: "update" (single job)
   - Runs-on: ubuntu-latest (standard for Bun workflows)
   - Steps:
     a. Checkout with actions/checkout@v4
     b. Setup Bun with oven-sh/setup-bun@v2 (matches existing CI pattern)
     c. Download schema (cd docs && bun run scripts/download-openapi.ts)
     d. Check for changes (git diff --quiet)
     e. Create PR with peter-evans/create-pull-request@v6

3. **Change detection:**
   - Use git diff to check if data.gv.at-openapi.yaml changed
   - Set output variable: `changed=true|false`
   - Only create PR if changed=true (avoid empty PRs)

4. **PR creation configuration:**
   - Action: peter-evans/create-pull-request@v6
   - Token: `${{ secrets.GITHUB_TOKEN }}` (built-in, no setup needed)
   - Branch: update-openapi-schema (consistent naming)
   - Delete branch: true (cleanup after merge)
   - Commit message: "docs: update data.gv.at OpenAPI schema" (conventional commits)
   - PR title: Clear, descriptive
   - PR body: Include source URL, checklist for reviewer

5. **Follow RESEARCH.md Pattern:**
   - Reference: Code Examples > "GitHub Actions Weekly Update Workflow"
   - Use exact structure from RESEARCH.md (HIGH confidence pattern)
   - Adapt commit message style to match project conventions (Phase 6 decisions)

**Why PR not direct commit:** RESEARCH.md Pitfall 3 - enables review of breaking schema changes before deployment.

**Why Monday 09:00 UTC:** Gives team time to review during work week before weekend.

**Why peter-evans/create-pull-request:** Industry-standard action with 5000+ stars, handles edge cases (existing PRs, conflicts, etc.).
