  <action>
Create sandbox lifecycle manager that tracks sandboxes in messages table with lazy cleanup strategy.

**Cleanup Strategy:**
- E2B built-in timeout: Sandboxes auto-terminate after 1 hour (no cron needed)
- try/finally cleanup: Always kill sandbox after code execution
- Lazy DB cleanup: Clear stale sandbox_id when message is accessed and sandbox has expired

This approach avoids paid cron services (Vercel Cron) and background jobs.

**docs/lib/sandbox/manager.ts:**
```typescript
import { db } from '@/db';
import { messages } from '@/db/schema';
import { eq, and, sql } from 'drizzle-orm';
import type { Sandbox } from '@e2b/code-interpreter';
import { createE2BClient } from '@/lib/mcp/e2b-client';

export interface TrackedSandbox {
  sandbox: Sandbox;
  messageId: number;
}

export async function createTrackedSandbox(
  messageId: number
): Promise<TrackedSandbox> {
  const e2bClient = createE2BClient({
    apiKey: process.env.E2B_API_KEY || '',
    timeoutMs: 60 * 60 * 1000, // 1 hour (EXEC-06) - E2B auto-terminates
  });

  const sandbox = await e2bClient.createSandbox();

  // Track in messages table where sandbox_id column exists (line 79 of schema.ts)
  await db
    .update(messages)
    .set({
      sandboxId: sandbox.sandboxId,
    })
    .where(eq(messages.id, messageId));

  return { sandbox, messageId };
}

export async function cleanupSandbox(messageId: number): Promise<void> {
  // Manual cleanup after code execution
  const message = await db.query.messages.findFirst({
    where: eq(messages.id, messageId),
  });

  if (!message?.sandboxId) {
    return; // No active sandbox
  }

  // Clear DB tracking (E2B already terminated sandbox if timeout reached)
  await db
    .update(messages)
    .set({
      sandboxId: null,
    })
    .where(eq(messages.id, messageId));
}

export async function cleanupStaleSandbox(messageId: number): Promise<void> {
  // Lazy cleanup: Clear sandbox_id if message is older than 1 hour
  // Call this when loading messages to keep DB clean
  await db
    .update(messages)
    .set({
      sandboxId: null,
    })
    .where(
      and(
        eq(messages.id, messageId),
        sql`sandbox_id IS NOT NULL`,
        sql`created_at < NOW() - INTERVAL '1 hour'`
      )
    );
}

export async function getSandboxForMessage(messageId: number): Promise<string | null> {
  // Get sandbox_id for message, automatically clean if stale
  await cleanupStaleSandbox(messageId);

  const message = await db.query.messages.findFirst({
    where: eq(messages.id, messageId),
    columns: {
      sandboxId: true,
    },
  });

  return message?.sandboxId || null;
}
```

Satisfies requirements:
- SEC-04: Each conversation uses isolated sandbox (tracked per message for code execution)
- EXEC-06: 1-hour timeout enforced via E2B's timeoutMs (auto-termination)
- Database tracking: sandbox_id column in messages table (line 79 of schema.ts)
- NO CRON NEEDED: Lazy cleanup on message access + E2B built-in timeout

**Cleanup Layers:**
1. **Primary:** try/finally in code execution (Plan 17 will implement)
2. **Timeout:** E2B auto-terminates after 1 hour
3. **Lazy:** cleanupStaleSandbox() called when loading messages

IMPORTANT: sandbox_id is stored in messages table, NOT conversations table. This correctly tracks which message triggered sandbox creation.

WHY message-level tracking: Code execution is message-specific. Multiple messages in same conversation may use different sandboxes.

WHY lazy cleanup: Avoids paid cron services (Vercel Cron), keeps architecture simple and open-source.
