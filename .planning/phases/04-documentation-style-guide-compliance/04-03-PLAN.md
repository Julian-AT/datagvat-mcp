For each file, apply:

**Guide-Specific Structure:**
- Add "When to Use This" sections (explain specific scenarios)
- Maintain task-oriented titles (existing titles like "Finding Datasets" are good)
- Focus on how-to guidance (prescriptive, not just descriptive)

**Style Principles:**
- Active voice, second person: "You configure" not "Configuration is done"
- Present tense: "The parameter controls" not "will control"
- Contractions allowed for natural tone
- Sentence case headings
- Short sentences (<25 words)
- Code examples before explanations

**Replace Generic Examples:**
- Use real Austrian dataset names in all examples
- Replace fictional dataset IDs with actual data.gv.at catalog IDs
- Use real Vienna, Austria regional examples

**Remove AI Buzzwords:**
- Delete: delve, leverage, utilize, harness, robust, comprehensive, seamless
- Replace with direct technical language

**Remove Generic Openers:**
- Delete: "In today's...", "In the realm of..."
- Start with specific use case or action

**Why:** Guides bridge concepts and workflows - must clearly state when to use each technique. Professional tone establishes authority and trust in technical guidance.

**Preserve:**
- TypeTable component usage for parameter documentation
- Tabs component for Basic/Advanced examples
- Internal links (verified in Phase 3)
- Frontmatter metadata
- German content structure in .de.mdx files
