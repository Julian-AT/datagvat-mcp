**File-by-file processing order:**

4. getting-started.mdx (tutorials)

For each file, apply:

**Prescriptive Guidance (Critical for Integration):**
- Be prescriptive, not descriptive: "Add this to claude_desktop_config.json" not "Configuration can be added"
- Show exact file paths: `~/.config/claude/claude_desktop_config.json` on macOS
- Provide complete working config examples (copy-pasteable)

**Index Page Special Attention:**
- Landing page sets tone for entire documentation
- Must demonstrate professional quality immediately
- Clear value proposition without marketing language
- Action-first: get users to quickstart quickly
- Remove phrases like "revolutionary", "cutting-edge", "game-changing"

**Style Principles:**
- Active voice, second person: "You configure" not "Configuration is done"
- Present tense: "The integration requires" not "will require"
- Contractions allowed for natural tone
- Sentence case headings
- Short sentences (<25 words)
- Code examples before explanations

**Real Examples:**
- Integration pages: Show real Claude Desktop config paths, real MCP server names
- Use actual file paths for different OS
- Show real working configuration JSON

**Remove AI Buzzwords:**
- Delete: delve, leverage, utilize, harness, robust, comprehensive, seamless
- Replace with direct actionable language (configure, implement, set, use)

**Remove Generic Openers:**
- Delete: "In today's...", "In the realm of..."
- Start with specific action or context

**Why:** Integration pages are WHERE USERS CONFIGURE SYSTEMS. Vague guidance leads to misconfiguration. Prescriptive examples enable immediate correct usage. Landing page is first impression of documentation quality.

**Preserve:**
- Fumadocs component imports (Cards, Tabs, Callout)
- Internal links (verified in Phase 3)
- Frontmatter metadata
- German content structure in .de.mdx files
