  <action>
Apply Microsoft/Google style guide conventions to all getting-started pages:

**Style Principles:**
- Active voice, second person: "You can search datasets" not "Datasets can be searched"
- Present tense: "The tool returns results" not "The tool will return results"
- Contractions allowed: "don't" not "do not" for natural tone
- Sentence case headings: "Getting started" not "Getting Started"
- Serial comma: "red, white, and blue"
- Short sentences: <25 words preferred
- Code before explanation: Show example first, then explain
- Specific over generic: Use real dataset names

**Replace Generic Examples with Real Austrian Datasets:**
- "Vienna Population Statistics 2023" → "Bevölkerung Wien 2020-2024" (actual dataset ID from data.gv.at)
- "Vienna Demographics Historical Data" → Use real dataset name and ID
- All fictional dataset IDs (abc-123, def-456) → Real IDs from catalog

**Remove AI Buzzwords:**
- Delete: delve, leverage, utilize, harness, robust, comprehensive, seamless
- Replace with direct, specific language

**Remove Generic Openers:**
- Delete: "In today's...", "In the realm of..."
- Start with action or specific information

**Other Improvements:**
- Reduce excessive em-dashes
- Vary sentence structure for readability
- Ensure professional code comments (no casual language)

**Why:** Getting started pages are first user contact - must demonstrate professional quality immediately. Real examples build confidence that tool works with actual data.gv.at catalog.

**Preserve:**
- All Fumadocs component imports (Callout, Steps, Tabs)
- Internal link paths (validation in Phase 3 ensured correctness)
- Frontmatter metadata (title, description)
- German content structure in .de.mdx files
