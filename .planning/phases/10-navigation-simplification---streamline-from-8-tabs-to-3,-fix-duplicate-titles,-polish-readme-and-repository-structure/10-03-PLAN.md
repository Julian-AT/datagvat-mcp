## Quick Start

Get your first dataset in under 5 minutes:

### 1. Install the MCP Server

```bash
# Clone repository
git clone https://github.com/datagvat/datagvat-mcp.git
cd datagvat-mcp

# Set up Python environment
uv venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate

# Install dependencies
uv pip install -e .
```

### 2. Configure Claude Desktop

**macOS:**
```bash
code ~/Library/Application\ Support/Claude/claude_desktop_config.json
```

**Windows:**
```bash
code %APPDATA%\Claude\claude_desktop_config.json
```

Add configuration:
```json
{
  "mcpServers": {
    "datagvat": {
      "command": "uv",
      "args": [
        "--directory",
        "/absolute/path/to/datagvat-mcp",
        "run",
        "datagvat-mcp"
      ]
    }
  }
}
```

### 3. Try Your First Query

Restart Claude Desktop and ask:

> "Find datasets about Vienna population"

# Contributing to data.gv.at MCP Server

Thank you for considering contributing to data.gv.at MCP Server! This document provides guidelines for contributing to the project.

## Ways to Contribute

- **Report bugs** - File issues with reproduction steps
- **Suggest features** - Propose new capabilities or improvements
- **Improve documentation** - Fix typos, clarify explanations, add examples
- **Submit code** - Fix bugs, add features, improve performance
- **Write tests** - Increase test coverage

## Getting Started

### Development Setup

1. **Fork and clone:**
   ```bash
   git clone https://github.com/YOUR_USERNAME/datagvat-mcp.git
   cd datagvat-mcp
   ```

2. **Set up Python environment:**
   ```bash
   uv venv
   source .venv/bin/activate  # Windows: .venv\Scripts\activate
   uv pip install -e ".[dev]"
   ```

3. **Run tests:**
   ```bash
   pytest
   ```

4. **Set up documentation (optional):**
   ```bash
   cd docs
   bun install
   bun dev
   ```

### Code Standards

**Python Code:**
- Follow PEP 8 style guide
- Use type hints (mypy --strict compliance)
- Write docstrings for all public functions
- Keep functions focused and testable

**Documentation:**
- Use Biome for TypeScript/MDX formatting
- Follow Microsoft Writing Style Guide
- Test all code examples
- Include visual aids where helpful

**Testing:**
- Write tests for new features
- Maintain existing test coverage
- Use pytest fixtures for common setups
- Mock external API calls

### Running Checks

```bash
# Python type checking
mypy src/

# Python tests
pytest

# Documentation linting
cd docs
bun lint
bun type-check

# Documentation link validation
bun run lint:links
```

## Pull Request Process

1. **Create feature branch:**
   ```bash
   git checkout -b feature/your-feature-name
   ```

2. **Make changes:**
   - Follow code standards
   - Add tests for new functionality
   - Update documentation if needed

3. **Commit changes:**
   ```bash
   git add .
   git commit -m "feat: add feature description"
   ```

   Use conventional commits:
   - `feat:` - New feature
   - `fix:` - Bug fix
   - `docs:` - Documentation changes
   - `test:` - Test additions or fixes
   - `refactor:` - Code refactoring
   - `chore:` - Maintenance tasks

4. **Push and create PR:**
   ```bash
   git push origin feature/your-feature-name
   ```

   Open pull request on GitHub with:
   - Clear description of changes
   - Link to related issues
   - Screenshots for UI changes
   - Test results

5. **Code review:**
   - Respond to feedback
   - Make requested changes
   - Keep commits atomic and focused

6. **Merge:**
   - PRs require maintainer approval
   - All CI checks must pass
   - Squash or rebase as requested

## Documentation Contributions

Documentation lives in `docs/` directory using Fumadocs framework.

### Adding Pages

1. Create MDX file in appropriate section:
   ```
   docs/content/docs/docs/your-section/your-page.mdx
   ```

2. Add frontmatter:
   ```mdx
   ---
   title: Page Title
   description: Brief description for SEO
   ---

   Content starts here (no manual # heading)
   ```

3. Update meta.json:
   ```json
   {
     "pages": [
       "existing-page",
       "your-page"
     ]
   }
   ```

4. Test locally:
   ```bash
   cd docs
   bun dev
   ```

### Documentation Standards

- Start content at H2 level (no manual H1)
- Use code blocks with language tags
- Test all code examples
- Add visual aids (Mermaid diagrams, screenshots)
- Link to related pages
