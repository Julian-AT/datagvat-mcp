  <action>
    Create `docs/lib/rag/chunker.ts` for semantic chunking:
    - Export `chunkDocumentation(mdxContent: string, docUrl: string, docTitle: string): Chunk[]`
    - Use unified + remark-parse + remark-mdx to parse MDX AST (already installed)
    - Use unist-util-visit to traverse AST (already installed at unist-util-visit@5.1.0)
    - Split on H2 (depth=2) and H3 (depth=3) heading nodes
    - Extract text from paragraph, code, and list nodes
    - Build chunks with 100-token overlap (keep last ~100 tokens from previous section)
    - Generate section URLs with slugified heading text (e.g., `/docs/quickstart#installation`)
    - Filter chunks smaller than 200 characters (avoid low-signal fragments)
    - Target 800-1200 tokens per chunk, but prioritize semantic boundaries (don't split mid-section)

    Create `docs/lib/rag/embedder.ts` for batch embedding:
    - Export `embedTexts(texts: string[]): Promise<{ embeddings: number[][], usage: { tokens: number } }>`
    - Use Vercel AI SDK's `embedMany()` function (from 'ai' package)
    - Configure with OpenAI text-embedding-3-small model (1536 dimensions)
    - Use createOpenAI from '@ai-sdk/openai-compatible' (already installed)
    - Set maxRetries: 2, maxParallelCalls: 3 for rate limit handling
    - Export `embedSingle(text: string)` wrapper for single embeddings
    - Use OPENAI_API_KEY environment variable

    DO NOT use LangChain (deprecated, heavy). DO use Vercel AI SDK's native embedMany().

    Chunk interface:
    ```typescript
    interface Chunk {
      text: string;
      url: string;
      title: string;
      section: string;
    }
    ```

    Helper function for slugification (basic version):
    ```typescript
    function slugify(text: string): string {
      return text.toLowerCase().replace(/\s+/g, '-').replace(/[^a-z0-9-]/g, '');
    }
    ```
  </action>
