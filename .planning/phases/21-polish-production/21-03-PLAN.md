# Plan 21-03: Remove Code Approval & Optimize UX

**Goal:** Remove the explicit code approval step to streamline the user experience, ensuring code runs immediately and outputs are displayed as soon as possible.

**Files to Modify:**
1.  `docs/components/sandbox-artifact.tsx` - Remove approval UI logic, auto-run on mount/update.
2.  `docs/hooks/use-sandbox.ts` - Remove `showApproval` and `hasApprovedOnce` state.
3.  `docs/lib/db/schema.ts` - Remove `hasApprovedOnce` column (optional, can keep for legacy compatibility or remove in migration).
4.  `docs/lib/db/queries.ts` - Remove `hasApprovedOnce` usage.
5.  `docs/lib/ai/prompts.ts` - Update prompts to reflect immediate execution.
6.  `docs/lib/ai/tools/open-sandbox.ts` - Remove approval references.

**Implementation Details:**

*   **Sandbox Artifact:**
    *   On mount (or when code arrives via stream), immediately trigger `handleRun`.
    *   Remove `SandboxCodeTab` approval buttons/overlay.
    *   Keep "Run" button for manual re-execution.
    *   Ensure `handleRun` is idempotent or debounced if called frequently during streaming (best to wait for `data-finish`).

*   **UX Optimization:**
    *   Show a "Initializing environment..." spinner for React templates during the bootstrap phase.
    *   Switch to "Output/Preview" tab immediately upon execution start.

*   **Security Note:**
    *   We are trusting the LLM output. Since E2B sandboxes are isolated, this is generally safe for the host system. The main risk is the LLM doing something unexpected, but user intent is "do task", so immediate execution matches expectations.

**Step-by-Step:**
1.  Modify `use-sandbox.ts` to remove approval states.
2.  Update `sandbox-artifact.tsx` to remove approval UI and trigger `handleRun` automatically.
3.  Update prompts to remove "approval required" language.
4.  Verify seamless execution flow.
