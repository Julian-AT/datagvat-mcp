# Installation & Setup

Get the Austria MCP server running in your Claude Desktop environment in minutes.

## Prerequisites

Before installing, ensure you have:

- **Python 3.11 or higher** - [Download Python](https://www.python.org/downloads/)
- **pip or uv package manager** - uv recommended for faster installs
- **Claude Desktop** or compatible MCP client - [Download Claude Desktop](https://claude.ai/download)

## How Austria MCP Works

Understanding the data flow helps you troubleshoot issues and optimize your queries:

```
   User: "Find population datasets from 2023"
      │
      ▼
┌─────────────────────────────────────────────┐
│         Claude Desktop                      │
│  Interprets → Calls search_datasets tool   │
└──────────────────┬──────────────────────────┘
                   │ MCP Protocol (stdio)
                   ▼
┌─────────────────────────────────────────────┐
│      Austria MCP Server receives request   │
│                                             │
│  1. Middleware processing:                 │
│     • Logging (record request)             │
│     • Auth validation                      │
│     • Rate limiting check                  │
│                                             │
│  2. Tool execution:                        │
│     • Parse parameters                     │
│     • Semantic query expansion (LLM)       │
│     • Build API request                    │
└──────────────────┬──────────────────────────┘
                   │ HTTPS GET
                   ▼
┌─────────────────────────────────────────────┐
│   Piveau API searches catalog              │
│   (data.gv.at)                             │
└──────────────────┬──────────────────────────┘
                   │ JSON response
                   ▼
┌─────────────────────────────────────────────┐
│  Server processes and enhances results:    │
│     • Quality scoring (metadata analysis)  │
│     • Theme enrichment (EU vocabularies)   │
│     • Semantic ranking (relevance boost)   │
│     • Format structured response           │
└──────────────────┬──────────────────────────┘
                   │ MCP response
                   ▼
┌─────────────────────────────────────────────┐
│   Claude Desktop receives structured data  │
│   Presents natural language summary        │
└─────────────────────────────────────────────┘
      │
      ▼
   User: "Population 2023 datasets:
          • Vienna Population Statistics (quality: 95)
          • National Demographics 2023 (quality: 87)
          ..."
```

**Why use the MCP server?**

The server adds value beyond direct API access:
- **Semantic understanding** - Expands queries with related terms
- **Quality scoring** - Ranks datasets by metadata completeness
- **Data previews** - Inspects CSV/JSON contents before download
- **Error handling** - Retries failed requests with exponential backoff
- **Rate limiting** - Protects against API throttling

## Installation

### Using uv (Recommended)

[uv](https://github.com/astral-sh/uv) is a fast Python package manager that provides better dependency resolution and faster installs.

## Configuration

### Claude Desktop Setup

Add the Austria MCP server to your Claude Desktop configuration:

**Location:** `~/.claude/claude_desktop_config.json` (macOS/Linux) or `%APPDATA%\Claude\claude_desktop_config.json` (Windows)

**Configuration:**

```json
{
  "mcpServers": {
    "datagvat-local": {
      "command": "uv",
      "args": [
        "run",
        "--directory",
        "/absolute/path/to/datagvat-mcp/mcp",
        "python",
        "-m",
        "app.server"
      ]
    }
  }
}
```

**Important:** Replace `/absolute/path/to/datagvat-mcp/mcp` with the actual path to the server directory in your cloned repository.

<Callout type="warn">
**Path Requirements:**
- Use absolute paths only (no `~` or relative paths)
- Windows: Use double backslashes (`C:\\Users\\...`)
- The path must point to the `mcp/` directory containing the `app/` folder
</Callout>

**Windows example:**
```json
{
  "mcpServers": {
    "datagvat-local": {
      "command": "uv",
      "args": [
        "run",
        "--directory",
        "C:\\Users\\YourName\\datagvat-mcp\\mcp",
        "python",
        "-m",
        "app.server"
      ]
    }
  }
}
```

**macOS/Linux example:**
```json
{
  "mcpServers": {
    "datagvat-local": {
      "command": "uv",
      "args": [
        "run",
        "--directory",
        "/Users/yourname/datagvat-mcp/mcp",
        "python",
        "-m",
        "app.server"
      ]
    }
  }
}
```

### Using pip instead of uv

If you prefer pip over uv:

```json
{
  "mcpServers": {
    "datagvat-pip": {
      "command": "python",
      "args": [
        "-m",
        "app.server"
      ],
      "cwd": "/absolute/path/to/datagvat-mcp/mcp"
    }
  }
}
```

## Environment Variables

Optional configuration via `.env` file in the project root:

```bash
# API Configuration
AUSTRIA_MCP_PIVEAU_API_BASE=https://www.data.gv.at/api/hub/search
AUSTRIA_MCP_REQUEST_TIMEOUT=30

# Logging
AUSTRIA_MCP_LOG_LEVEL=INFO
AUSTRIA_MCP_LOG_FORMAT=json

# Development
AUSTRIA_MCP_DEV_MODE=false
```

### Available Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `AUSTRIA_MCP_PIVEAU_API_BASE` | `https://www.data.gv.at/api/hub/search` | Piveau API base URL |
| `AUSTRIA_MCP_REQUEST_TIMEOUT` | `30` | Request timeout in seconds |
| `AUSTRIA_MCP_LOG_LEVEL` | `INFO` | Logging level (DEBUG, INFO, WARNING, ERROR) |
| `AUSTRIA_MCP_LOG_FORMAT` | `json` | Log format (json, text) |
| `AUSTRIA_MCP_DEV_MODE` | `false` | Enable development features |

## Test Server Locally

Before configuring Claude Desktop, verify the server works correctly:

### 1. Test Server Import

```bash
python -c "from app.server import mcp; print('✅ Server loads successfully')"
```

This confirms all dependencies are installed and the server code is valid.

### 2. Run Development Mode

```bash
fastmcp dev app.server:mcp
```

This starts FastMCP's development server with a web interface at `http://localhost:8000` where you can:

- Browse all available tools
- Test tool execution with sample parameters
- View server logs in real-time
- Verify responses before Claude Desktop integration

### 3. Expected Tools

The development UI should show these tool categories:

**Discovery Tools:**
- `list_catalogues` - Browse available data catalogues
- `search_datasets` - Search for datasets
- `get_dataset` - Retrieve dataset details
- `list_dataset_distributions` - Get dataset download links

**Management Tools:**
- `create_dataset_draft` - Create new dataset drafts
- `update_dataset` - Update existing datasets
- `delete_dataset` - Remove datasets

**Analysis Tools:**
- `analyze_dataset_quality` - Calculate metadata quality score
- `find_related_datasets` - Discover similar datasets

**Vocabulary Tools:**
- `list_vocabularies` - Browse EU DCAT-AP vocabularies
- `search_vocabulary_terms` - Search vocabulary terms

**Preview Tools:**
- `preview_dataset_file` - Sample data from CSV/JSON files

### 4. Test Basic Functionality

In the dev UI, try `list_catalogues` with `limit=3`:

**Expected response:**
```json
[
  {"id": "data-gv-at", "title": "data.gv.at"},
  {"id": "stadt-wien", "title": "Stadt Wien Open Data"},
  {"id": "land-karnten", "title": "Land Kärnten"}
]
```

If you see this response, the server is working correctly and ready for Claude Desktop.

## Troubleshooting

### Server not appearing in Claude Desktop

1. **Check config file syntax** - Ensure JSON is valid (no trailing commas, proper quotes)
2. **Verify paths** - Use absolute paths, not relative paths or `~`
3. **Restart Claude Desktop** - Configuration is only loaded on startup (fully quit, not just close window)
4. **Check logs** - Look in Claude Desktop logs for MCP server errors

<Callout type="info">
**Log Locations:**
- **Windows:** `%APPDATA%\Claude\logs\`
- **macOS:** `~/Library/Logs/Claude/`
- **Linux:** `~/.config/Claude/logs/`
</Callout>

### Wrong working directory

**Symptom:** `ModuleNotFoundError: No module named 'app'`

**Cause:** The `cwd` path doesn't point to the `mcp/` directory.

**Fix:** Ensure your config points to the directory containing the `app/` folder.

The correct directory structure looks like this:

```
datagvat-mcp/                    ❌ cwd="..." (too high - repo root)
  ├── docs/
  ├── .planning/
  └── mcp/                       ✅ cwd=".../mcp" (CORRECT - contains app/)
      ├── app/                   ❌ cwd=".../app" (too low - inside app/)
      │   ├── server.py
      │   ├── client.py
      │   ├── tools/
      │   └── ...
      ├── tests/
      ├── pyproject.toml
      ├── .env
      └── README.md
```

Your configuration must point to the `mcp/` directory:

```json
{
  "cwd": "/absolute/path/to/datagvat-mcp/mcp"
}
```

**Common mistakes:**
- ❌ `/datagvat-mcp` - Too high (repo root, no `app/` folder here)
- ❌ `/datagvat-mcp/mcp/app` - Too low (Python can't import from inside `app/`)
- ✅ `/datagvat-mcp/mcp` - Correct (contains `app/` as a Python package)

### Command not found

**Symptom:** Error mentions "datagvat-mcp" command not found

**Cause:** Using outdated configuration from earlier documentation versions.

**Fix:** Use the corrected configurations shown above. The server runs as a Python module (`python -m app.server`), not as a standalone command.

### Server appears but tools don't work

**Symptoms:**
- Claude Desktop shows server connected
- Tool execution results in errors

**Debug steps:**

1. **Check Python version:**
```bash
python --version  # Must be 3.11 or higher
```

2. **Test server locally:**
```bash
python -m app.server  # Should start without errors
```

3. **Try development mode:**
```bash
fastmcp dev app.server:mcp  # Test tools in web UI
```

4. **Check Claude Desktop logs** for specific error messages

### Server keeps disconnecting

**Symptoms:**
- Server connects initially
- Disconnects after first use or randomly

**Possible causes:**
- Server crash due to unhandled exception
- Network/firewall blocking API requests
- Python environment mismatch

**Debug steps:**

1. **Check logs for crash messages** in Claude Desktop logs directory
2. **Test API access directly:**
```bash
curl https://www.data.gv.at/api/hub/search/catalogues
```

3. **Run server directly to see errors:**
```bash
python -m app.server
```

### Connection errors

If you see connection errors when tools execute:

1. **Test API access** directly:
```bash
curl https://www.data.gv.at/api/hub/search/catalogues
```

2. **Check firewall settings** - Ensure outbound HTTPS is allowed
3. **Verify network** - Try from a different network if behind corporate firewall

### Import errors

If you see Python import errors:

1. **Verify Python version:**
```bash
python --version  # Should be 3.11 or higher
```

2. **Reinstall dependencies:**
```bash
uv pip install -e . --force-reinstall
# or with pip:
pip install -e . --force-reinstall
```

3. **Check virtual environment** - Ensure you're using the correct Python environment

4. **Try absolute Python path** in config to avoid version mismatches:
```json
{
  "command": "C:\\Python311\\python.exe",  // Windows
  "args": ["-m", "app.server"],
  "cwd": "C:\\path\\to\\datagvat-mcp\\mcp"
}
```
