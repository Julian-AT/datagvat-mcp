# FastMCP Framework Internals

Understanding FastMCP's internal patterns enables you to build production-ready MCP servers, extend data.gv.at MCP Server, and create custom integrations. This guide documents the patterns that make data.gv.at MCP Server reliable and maintainable.

## Introduction

### What FastMCP Abstracts

FastMCP is a framework that abstracts the complexity of the Model Context Protocol (MCP), handling:

- **MCP Protocol Implementation** - JSON-RPC 2.0 message handling, capability negotiation
- **Transport Layer** - stdio and SSE communication with clients
- **Type System** - Automatic JSON Schema generation from Python type hints
- **Lifecycle Management** - Server startup, shutdown, and state management
- **Error Handling** - Exception conversion to MCP-compliant error responses

Without FastMCP, implementing these features requires approximately **500+ lines of boilerplate code** for protocol handling, message parsing, schema generation, and transport management.

### When to Use FastMCP vs Raw MCP SDK

**Use FastMCP when:**
- Building production MCP servers with multiple tools
- You want type-safe tool definitions with automatic validation
- You need middleware for logging, auth, rate limiting, etc.
- You prefer declarative, decorator-based APIs

**Use Raw MCP SDK when:**
- Building minimal proof-of-concept servers
- You need complete control over protocol details
- Your use case doesn't fit FastMCP's patterns
- You're implementing custom transports

### data.gv.at MCP Server as Reference Implementation

data.gv.at MCP Server demonstrates production-ready FastMCP patterns:

- **60+ Tools** across 5 categories (discovery, management, analysis, preview, vocabularies)
- **6-Layer Middleware Stack** (logging, error handling, retry, rate limiting, audit, auth)
- **Semantic Query Expansion** using LLM-powered natural language understanding
- **Quality Scoring** with DQV-compliant metadata analysis
- **Connection Pooling** with httpx for efficient API calls
- **Type-Safe Configuration** using pydantic-settings

All code examples in this guide are extracted from the data.gv.at MCP Server codebase.

## Decorator-Based Tool Registration

FastMCP uses Python decorators to register tools, automatically generating JSON Schemas from type hints and docstrings.

### Basic Tool Pattern

```python
from fastmcp import FastMCP, Context
from typing import Annotated
from pydantic import Field

mcp = FastMCP(name="my-server")

@mcp.tool()
async def search_datasets(
    ctx: Context,
    query: str | None = None,
    limit: Annotated[int, Field(ge=1, le=100)] = 20,
) -> dict[str, Any]:
    """
    Search for datasets using keywords.

    Args:
        ctx: FastMCP context (provides state, logging, progress)
        query: Search keywords (optional)
        limit: Maximum results (1-100, default 20)

    Returns:
        Search results with metadata and facets
    """
    # Tool implementation
    return {"results": [...]}
```

### Schema Generation

FastMCP automatically generates this JSON Schema from the function signature:

```json
{
  "name": "search_datasets",
  "description": "Search for datasets using keywords.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": {
        "type": ["string", "null"],
        "description": "Search keywords (optional)"
      },
      "limit": {
        "type": "integer",
        "minimum": 1,
        "maximum": 100,
        "default": 20,
        "description": "Maximum results (1-100, default 20)"
      }
    },
    "required": []
  }
}
```

**Key features:**
- `Context` parameter is automatically excluded from schema
- `Annotated[int, Field(...)]` becomes validation constraints
- Docstrings populate `description` fields
- Optional parameters use JSON Schema `"type": [..., "null"]`

### Real Example from data.gv.at MCP Server

From `mcp/app/tools/discovery.py`:

```python
@mcp.tool(
    name="list_catalogues",
    description="List available data catalogues in the Austrian Open Data Portal.",
    annotations={"readOnlyHint": True},
)
async def list_catalogues(
    ctx: Context,
    limit: Annotated[int, Field(ge=1, le=5000, description="Maximum number of catalogues to return (1-5000)")] = 100,
    offset: Annotated[int, Field(ge=0, description="Number of catalogues to skip for pagination")] = 0,
    value_type: Annotated[str, Field(description="Type of value to return: 'id' for IDs only, 'metadata' for full metadata")] = "metadata",
) -> list[dict[str, Any]]:
    client = get_piveau_client(ctx)
    try:
        if ctx:
            await ctx.report_progress(0, 1, "Fetching catalogues...")
        vt = ValueType(value_type) if value_type in [e.value for e in ValueType] else ValueType.METADATA
        result = await client.list_catalogues(limit=limit, offset=offset, value_type=vt)
        if ctx:
            await ctx.report_progress(1, 1, f"Retrieved {len(result)} catalogues")
        return result
    except Exception as e:
        raise ToolError(f"Failed to list catalogues: {e}") from e
```

**Pattern highlights:**
- `annotations={"readOnlyHint": True}` hints to clients that tool is read-only
- Multiple `Annotated[type, Field(...)]` constraints for validation
- Progress reporting using `ctx.report_progress(current, total, message)`
- Exception conversion to `ToolError` for MCP-compliant error responses

### Parameter Validation

FastMCP uses Pydantic for automatic validation:

```python
from pydantic import Field, StringConstraints
from typing import Annotated

@mcp.tool()
async def create_dataset(
    ctx: Context,
    title: Annotated[str, StringConstraints(min_length=3, max_length=200)],
    description: Annotated[str, StringConstraints(min_length=10)],
    tags: Annotated[list[str], Field(min_length=1, max_length=20)],

    """Create a new dataset with validated parameters."""
    # Pydantic has already validated:
    # - title is 3-200 chars
    # - description is at least 10 chars
    # - tags has 1-20 items
    ...
```

## Context Injection

`Context` is FastMCP's dependency injection mechanism, providing access to:

- **Application State** - Shared resources (HTTP clients, databases, config)
- **Logging** - Structured logging with correlation IDs
- **Progress Reporting** - Long-running operation feedback
- **LLM Sampling** - Request LLM assistance from clients
- **Request Metadata** - Request ID, client info, timestamps

### Context Pattern

**Always use `ctx: Context` as the first parameter in tools:**

```python
from fastmcp import Context

@mcp.tool()
async def my_tool(ctx: Context, param: str) -> dict:
    # Context provides:
    # - ctx.request_context.lifespan_context (app state)
    # - ctx.request_id (correlation ID)
    # - ctx.report_progress(current, total, message)
    # - ctx.sample_text(prompt, temperature)
    # - ctx.logger (structured logging)
    ...
```

**Note:** The `ctx` parameter is automatically injected by FastMCP and excluded from tool schemas.

### Accessing Application State

Application state is created during lifespan initialization and accessed via Context:

```python
from dataclasses import dataclass
from fastmcp import FastMCP, Context
from contextlib import asynccontextmanager

@dataclass
class AppState:
    """Application state available to all tools."""
    settings: Settings
    piveau_client: PiveauClient
    # Add any shared resources (DB connections, HTTP clients, etc.)

@asynccontextmanager
async def lifespan(mcp: FastMCP):
    """Initialize and cleanup application resources."""
    settings = get_settings()
    client = PiveauClient(base_url=settings.api_url, timeout=30)

    try:
        yield AppState(settings=settings, piveau_client=client)
    finally:
        await client.close()  # Cleanup on shutdown

mcp = FastMCP(
    name="my-server",
    lifespan=lifespan,  # Attach lifespan handler
)

# Access state in tools
@mcp.tool()
async def search(ctx: Context, query: str) -> dict:
    # Get app state from Context
    app_state = ctx.request_context.lifespan_context
    client = app_state.piveau_client

    # Use shared client for API calls
    results = await client.search(query)
    return results
```

For long-running operations, use `ctx.report_progress()` to provide feedback:

Claude and other MCP clients display progress to users, improving UX for slow operations.

### Request Correlation

Use `ctx.request_id` for tracing requests across logs:

```python
import logging

logger = logging.getLogger(__name__)

@mcp.tool()
async def complex_operation(ctx: Context, param: str) -> dict:
    req_id = ctx.request_id or "no-id"
    logger.info(f"[{req_id}] Starting complex_operation with param={param}")

    try:
        result = await do_work(param)
        logger.info(f"[{req_id}] complex_operation succeeded")
        return result
    except Exception as e:
        logger.error(f"[{req_id}] complex_operation failed: {e}")
        raise
```

All logs for a single request share the same correlation ID, simplifying debugging.

## Middleware Development

FastMCP middleware intercepts tool calls for cross-cutting concerns like logging, auth, rate limiting, and error handling.

### Middleware vs Context

**FastMCP uses middleware hooks instead of explicit pipelines:**

- Traditional frameworks: `app.use(middleware1).use(middleware2)`
- FastMCP: Middleware list with `on_call_tool` hooks

**Middleware receives `MiddlewareContext` (not `Context`):**

- `MiddlewareContext` contains protocol-level details (tool name, arguments, message)
- Access FastMCP `Context` via `context.fastmcp_context`

### Basic Middleware Pattern

```python
from fastmcp.server.middleware import Middleware, MiddlewareContext
from typing import Any

class MyMiddleware(Middleware):
    """Custom middleware template."""

    async def on_call_tool(self, context: MiddlewareContext, call_next: Any) -> Any:
        # Pre-processing (before tool execution)
        tool_name = self._get_tool_name(context)
        print(f"Before: {tool_name}")

        # Call next middleware or tool
        try:
            result = await call_next(context)
        except Exception as e:
            # Handle exceptions
            print(f"Error in {tool_name}: {e}")
            raise

        # Post-processing (after tool execution)
        print(f"After: {tool_name}")

        return result

    def _get_tool_name(self, context: MiddlewareContext) -> str:
        """Helper to extract tool name from context."""
        try:
            if hasattr(context, "arguments") and context.arguments:
                return str(context.arguments.get("name", "unknown"))
        except Exception:
            pass
        return "unknown"
```

### Middleware Order Matters

**data.gv.at MCP Server middleware stack** (`mcp/app/server.py`):

```python
middleware=[
    StructuredLoggingMiddleware(      # 1. Log all requests
        include_payloads=False,
        include_payload_length=True,
        estimate_payload_tokens=True,
    ),
    ErrorHandlingMiddleware(),        # 2. Convert exceptions to MCP errors
    RetryMiddleware(                  # 3. Retry transient failures
        max_retries=3,
        base_delay=1.0,
        max_delay=60.0,
        backoff_multiplier=2.0,
        retry_exceptions=(ConnectionError, TimeoutError),
    ),
    RateLimitingMiddleware(           # 4. Enforce rate limits
        max_requests_per_second=10.0,
        burst_capacity=20,
        global_limit=False,
    ),
    AuditMiddleware(),                # 5. Audit tool usage (custom)
    AuthMiddleware(),                 # 6. Enforce API key auth (custom)
]
```

**Why order matters:**

```
Request Flow (Inbound):
┌────────────────────────────────────────┐
│ 1. StructuredLogging → logs start     │
│ 2. ErrorHandling → catches exceptions  │
│ 3. Retry → retries on failure         │
│ 4. RateLimiting → checks quota        │
│ 5. Audit → logs attempt                │
│ 6. Auth → validates credentials        │
│ 7. Tool Execution                      │
└────────────────────────────────────────┘

Response Flow (Outbound - reverse order):
┌────────────────────────────────────────┐
│ 7. Tool Result                         │
│ 6. Auth (no-op on response)            │
│ 5. Audit → logs timing                 │
│ 4. RateLimiting → updates quota        │
│ 3. Retry (no-op on success)            │
│ 2. ErrorHandling → formats errors      │
│ 1. StructuredLogging → logs completion │
└────────────────────────────────────────┘
```

**Bad ordering example:**

```python
# WRONG: Auth before ErrorHandling
middleware=[
    AuthMiddleware(),          # Auth exceptions bypass error handler!
    ErrorHandlingMiddleware(),
    ...
]

# WRONG: Audit before Logging
middleware=[
    AuditMiddleware(),         # Audit logs have no correlation ID!
    StructuredLoggingMiddleware(),
    ...
]

# CORRECT: Log → Error → Retry → Rate → Audit → Auth
middleware=[
    StructuredLoggingMiddleware(),  # Sets correlation ID
    ErrorHandlingMiddleware(),      # Catches all exceptions
    RetryMiddleware(),              # Retries transient failures
    RateLimitingMiddleware(),       # Rate limits after retries
    AuditMiddleware(),              # Logs attempts with correlation
    AuthMiddleware(),               # Auth last (fails fast)
]
```

### Real Middleware Examples

**AuditMiddleware** - Logs timing and outcomes (`mcp/app/middleware.py`):

```python
import logging
import time
from fastmcp.server.middleware import Middleware, MiddlewareContext
from typing import Any

logger = logging.getLogger(__name__)

class AuditMiddleware(Middleware):
    """Logs tool executions with timing."""

    async def on_call_tool(self, context: MiddlewareContext, call_next: Any) -> Any:
        tool_name = self._get_tool_name(context)
        request_id = self._get_request_id(context)
        start = time.perf_counter()

        logger.info(f"[{request_id}] {tool_name} started")

        try:
            result = await call_next(context)
            elapsed = (time.perf_counter() - start) * 1000
            logger.info(f"[{request_id}] {tool_name} completed in {elapsed:.2f}ms")
            return result
        except Exception as e:
            elapsed = (time.perf_counter() - start) * 1000
            logger.error(f"[{request_id}] {tool_name} failed after {elapsed:.2f}ms: {e}")
            raise

    def _get_tool_name(self, context: MiddlewareContext) -> str:
        try:
            if hasattr(context, "arguments") and context.arguments:
                name = context.arguments.get("name", "unknown")
                return str(name) if name is not None else "unknown"
            if hasattr(context, "message") and context.message:
                params = getattr(context.message, "params", None)
                if params:
                    name = getattr(params, "name", "unknown")
                    return str(name) if name is not None else "unknown"
        except Exception:
            pass
        return "unknown"

    def _get_request_id(self, context: MiddlewareContext) -> str:
        try:
            if context.fastmcp_context:
                req_id = context.fastmcp_context.request_id or "no-id"
                return str(req_id)
        except Exception:
            pass
        return f"req-{int(time.time() * 1000)}"
```

**AuthMiddleware** - API key validation for write operations (`mcp/app/middleware.py`):

```python
from fastmcp.exceptions import ToolError
from fastmcp.server.middleware import Middleware, MiddlewareContext
from typing import Any

class AuthMiddleware(Middleware):
    """Enforces API key for write operations."""

    WRITE_TOOLS = frozenset({
        "create_dataset_draft",
        "update_dataset_draft",
        "delete_dataset_draft",
        "publish_dataset",
        "hide_dataset",
    })

    async def on_call_tool(self, context: MiddlewareContext, call_next: Any) -> Any:
        tool_name = self._get_tool_name(context)

        if tool_name in self.WRITE_TOOLS:
            if not self._has_api_key(context):
                raise ToolError(
                    f"API key required for '{tool_name}'. "
                    "Set AUSTRIA_MCP_PIVEAU_API_KEY environment variable."
                )

        return await call_next(context)

    def _get_tool_name(self, context: MiddlewareContext) -> str:
        try:
            if hasattr(context, "arguments") and context.arguments:
                name = context.arguments.get("name", "")
                return str(name) if name is not None else ""
            if hasattr(context, "message") and context.message:
                params = getattr(context.message, "params", None)
                if params:
                    name = getattr(params, "name", "")
                    return str(name) if name is not None else ""
        except Exception:
            pass
        return ""

    def _has_api_key(self, context: MiddlewareContext) -> bool:
        try:
            if context.fastmcp_context and context.fastmcp_context.request_context:
                app_state = context.fastmcp_context.request_context.lifespan_context
                if app_state and hasattr(app_state, "settings"):
                    return app_state.settings.api_key_value is not None
        except Exception:
            pass
        return False
```

**Key pattern:** Access `Context` from middleware via `context.fastmcp_context.request_context.lifespan_context`.

### Accessing FastMCP Context in Middleware

```python
class MyMiddleware(Middleware):
```

## Lifespan Management & Type System

### Lifespan Pattern

Use async context manager for startup/shutdown:

```python
from contextlib import asynccontextmanager
from fastmcp import FastMCP
from dataclasses import dataclass
import httpx

@dataclass
class AppState:
    http_client: httpx.AsyncClient
    database: Database
    cache: Cache

@asynccontextmanager
async def lifespan(mcp: FastMCP):
    """Initialize resources on startup, cleanup on shutdown."""
    # Startup
    http_client = httpx.AsyncClient(timeout=30.0)
    database = await Database.connect("postgresql://...")
    cache = await Cache.connect("redis://...")

    print("Server starting...")

    try:
        # Yield state available to all tools
        yield AppState(
            http_client=http_client,
            database=database,
            cache=cache,
        )
    finally:
        # Shutdown (always executes, even on error)
        await http_client.aclose()
        await database.disconnect()
        await cache.disconnect()
        print("Server stopped")

mcp = FastMCP(name="my-server", lifespan=lifespan)
```

**Lifespan benefits:**
- Initialize expensive resources once (HTTP clients, DB connections)
- Share resources across all tools
- Guarantee cleanup on shutdown
- Centralize configuration loading

```python
Publisher: {dataset['publisher']}
Modified: {dataset.get('modified', 'unknown')}
Distributions: {len(dataset.get('distributions', []))}

Assess the quality across these dimensions:
1. Completeness (required metadata present?)
2. Timeliness (how recent is the data?)
3. Accuracy (are URLs accessible, formats valid?)
4. Consistency (language, theme assignments)
5. Compliance (DCAT-AP standard adherence)

Provide a quality score (0-100) and specific recommendations."""
```

### When to Use Resources vs Tools vs Prompts

| Feature | Use When | Example |
|---------|----------|---------|
| **Tool** | User wants to execute an action | `search_datasets`, `create_dataset` |
| **Resource** | User wants to read data directly | `dataset://abc-123`, `catalogue://vienna` |
| **Prompt** | User wants a structured workflow | Quality analysis, report generation |

**Rules of thumb:**
- Tools change state or fetch dynamic data
- Resources provide static/cached data access
- Prompts guide LLMs through multi-step processes

## Extension Patterns & Common Pitfalls

### Adding Custom Tools

**Template:**

```python
from fastmcp import Context, FastMCP
from fastmcp.exceptions import ToolError
from typing import Annotated
from pydantic import Field

def register_my_tools(mcp: FastMCP) -> None:
    """Register custom tools."""

    @mcp.tool()
    async def my_tool(
        ctx: Context,
        param1: Annotated[str, Field(min_length=1, max_length=100)],
        param2: int = 10,
    ) -> dict:
        """
        My custom tool description.

        Args:
            ctx: FastMCP context
            param1: Required parameter (1-100 chars)
            param2: Optional parameter (default 10)

        Returns:
            Result dictionary
        """
        # 1. Get dependencies from context
        app_state = ctx.request_context.lifespan_context
        client = app_state.http_client

        # 2. Report progress for long operations
        await ctx.report_progress(0, 1, "Processing...")

        try:
            # 3. Execute tool logic
            result = await client.fetch_data(param1, param2)

            await ctx.report_progress(1, 1, "Complete")
            return {"data": result}

        except Exception as e:
            # 4. Convert exceptions to ToolError
            raise ToolError(f"my_tool failed: {e}") from e

# Register in server.py
mcp = FastMCP(name="my-server", lifespan=lifespan)
register_my_tools(mcp)
```

### Adding Custom Middleware

**Template:**

```python
from fastmcp.server.middleware import Middleware, MiddlewareContext
from typing import Any
import time

class MyMiddleware(Middleware):
    """Custom middleware template."""

    def __init__(self, config_param: str):
        self.config = config_param

    async def on_call_tool(self, context: MiddlewareContext, call_next: Any) -> Any:
        # Extract tool name
        tool_name = self._get_tool_name(context)

        # Pre-processing
        start = time.perf_counter()
        print(f"[MyMiddleware] Before {tool_name}")

        try:
            # Call next middleware/tool
            result = await call_next(context)

            # Post-processing (success)
            elapsed = time.perf_counter() - start
            print(f"[MyMiddleware] After {tool_name} ({elapsed:.3f}s)")

            return result

        except Exception as e:
            # Post-processing (error)
            elapsed = time.perf_counter() - start
            print(f"[MyMiddleware] Error in {tool_name} ({elapsed:.3f}s): {e}")
            raise  # Re-raise to ErrorHandlingMiddleware

    def _get_tool_name(self, context: MiddlewareContext) -> str:
        try:
            if hasattr(context, "arguments") and context.arguments:
                return str(context.arguments.get("name", "unknown"))
        except Exception:
            pass
        return "unknown"

# Add to middleware stack
mcp = FastMCP(
    name="my-server",
    middleware=[
        StructuredLoggingMiddleware(),
        ErrorHandlingMiddleware(),
        MyMiddleware(config_param="value"),  # Add custom middleware
        ...
    ]
)
```

### Common Pitfalls

#### 1. Incorrect Middleware Order

**Symptom:** Auth exceptions bypass error handler, logs missing correlation IDs

**Wrong:**
```python
middleware=[
    AuthMiddleware(),          # ❌ Auth exceptions not formatted
    ErrorHandlingMiddleware(),
    StructuredLoggingMiddleware(),  # ❌ No correlation ID assigned
]
```

**Correct:**
```python
middleware=[
    StructuredLoggingMiddleware(),  # ✅ Assign correlation ID first
    ErrorHandlingMiddleware(),      # ✅ Catch all exceptions
    AuthMiddleware(),               # ✅ Auth errors properly formatted
]
```

**Diagnostic:** Check logs for missing correlation IDs or raw exception tracebacks in responses.

#### 2. Missing Context Usage

**Symptom:** Hardcoded config, no progress reporting, difficult testing

**Wrong:**
```python
# Hardcoded configuration
API_URL = "https://api.example.com"
client = httpx.AsyncClient(base_url=API_URL)

@mcp.tool()
async def search(query: str) -> dict:
    # No context, no progress, global state
    return await client.get("/search", params={"q": query})
```

**Correct:**
```python
@mcp.tool()
async def search(ctx: Context, query: str) -> dict:
    # Get client from context (testable, configurable)
    client = get_http_client(ctx)

    # Report progress
    await ctx.report_progress(0, 1, "Searching...")
    result = await client.get("/search", params={"q": query})
    await ctx.report_progress(1, 1, "Complete")

    return result
```

**Fix:** Always use `ctx: Context` first parameter, access state via `ctx.request_context.lifespan_context`.

#### 3. Hardcoded Configuration

**Symptom:** Can't change settings without code changes, difficult to deploy

**Wrong:**
```python
# Configuration in code
mcp = FastMCP(
    name="my-server",
    middleware=[
        RateLimitingMiddleware(max_requests_per_second=10.0),  # ❌ Hardcoded
    ]
)
```

**Correct:**
```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    rate_limit: float = 10.0
    model_config = SettingsConfigDict(env_prefix="MY_SERVER_")

@asynccontextmanager
async def lifespan(mcp: FastMCP):
    settings = Settings()  # ✅ From environment
    yield AppState(settings=settings)

settings = Settings()
mcp = FastMCP(
    name="my-server",
    middleware=[
        RateLimitingMiddleware(
            max_requests_per_second=settings.rate_limit  # ✅ Configurable
        ),
    ]
)
```

**Fix:** Use pydantic-settings with `env_prefix` for all configuration.

#### 4. Missing Type Hints

**Symptom:** Schema generation fails, validation doesn't work, IDE autocomplete broken

**Wrong:**
```python
@mcp.tool()
async def search(ctx, query, limit=20):  # ❌ No types
    ...
```

**Correct:**
```python
from typing import Annotated
from pydantic import Field

@mcp.tool()
async def search(
    ctx: Context,  # ✅ Context type
    query: str,    # ✅ Required str
    limit: Annotated[int, Field(ge=1, le=100)] = 20  # ✅ Validated int
) -> dict[str, Any]:  # ✅ Return type
    ...
```

**Fix:** Always use type hints for all parameters and return types.
