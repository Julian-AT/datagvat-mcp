## Research workflow pattern

**Goal:** Find, evaluate, and download datasets for research purposes

**When to use:** Academic research, literature reviews, citation-quality data needs

**Pattern:**

<Tabs items={['Overview', 'Detailed steps']} groupId="workflow-style" persist>
  <Tab value="Overview">
    ### Quick pattern

    1. Semantic search with quality boost
    2. Analyze quality scores (target 85+)
    3. Preview schema for required columns
    4. Verify license permits research use
    5. Download if all checks pass

    **Time:** 5-10 minutes per dataset

    **Success criteria:**
    - Quality score ≥85
    - All required columns present
    - License allows citation
    - Recent update (within 12 months)
  </Tab>

  <Tab value="Detailed steps">
    ### Step-by-step research pattern

    **Step 1: Targeted search**

    Use semantic search with quality boost:

    ```python
    results = semantic_search_datasets(
        natural_query="Wien Bevölkerungsstatistik Bezirke",
        boost_quality=True,
        limit=20
    )
    ```

    Filter for high-quality results (score >85).

    **Step 2: Quality verification**

    Analyze top candidates:

    ```python
    for dataset in results['results'][:5]:
        if dataset.get('quality_score', 0) >= 85:
            quality = analyze_dataset_quality(dataset['id'])
            print(f"{dataset['title']}: {quality['metrics']}")
    ```

    Check for completeness, timeliness, compliance.

    **Step 3: Schema validation**

    Verify required columns:

    ```python
    distributions = get_dataset_distributions(dataset_id)
    url = distributions[0]['downloadURL']
    schema = preview_schema(url=url)

    required = ["jahr", "bezirk", "einwohner"]
    actual = [c['name'] for c in schema['columns']]
    has_required = all(col in actual for col in required)
    ```

    **Step 4: License check**

    ```python
    dataset = get_dataset(dataset_id)
    license = dataset.get('license')
    # Verify license allows research use
    # Common research-friendly: CC-BY, CC0, ODbL
    ```

    **Step 5: Download decision**

    If all checks pass:
    - [ ] Quality score ≥85
    - [ ] Required columns present
    - [ ] Research-friendly license
    - [ ] Recent update

    Proceed with download using URL from distributions.

## Validation workflow pattern

**Goal:** Verify dataset meets requirements before production use

**When to use:** Application integration, production pipelines, data quality assurance

**Pattern:**

<Tabs items={['Overview', 'Detailed steps']} persist groupId="workflow-style">
  <Tab value="Overview">
    ### Quick pattern

    1. Get dataset metadata
    2. Check quality score (target 70+)
    3. Preview schema and sample data
    4. Validate data types match expectations
    5. Test download URL accessibility
    6. Approve for production use

    **Time:** 10-15 minutes per dataset

    **Success criteria:**
    - Quality score ≥70
    - Schema matches requirements
    - Data types correct
    - Download URL accessible
    - No truncated or corrupt data
  </Tab>

  <Tab value="Detailed steps">
    ### Step-by-step validation pattern

    **Step 1: Metadata check**

    ```python
    dataset = get_dataset(dataset_id)
    required_fields = ['title', 'description', 'license', 'publisher']
    missing = [f for f in required_fields if not dataset.get(f)]
    if missing:
        print(f"Missing metadata: {missing}")
    ```

    **Step 2: Quality assessment**

    ```python
    quality = analyze_dataset_quality(dataset_id)
    if quality['metrics']['overall_score'] < 70:
        print("Quality below production threshold")
        # Review quality breakdown
        print(quality['metadata'])
    ```

    **Step 3: Schema validation**

    ```python
    distributions = get_dataset_distributions(dataset_id)
    url = next(d['downloadURL'] for d in distributions
               if d.get('format') == 'CSV')

    schema = preview_schema(url=url)

    # Validate columns
    required_columns = ["id", "timestamp", "value"]
    actual_columns = [c['name'] for c in schema['columns']]
    missing_cols = set(required_columns) - set(actual_columns)

    if missing_cols:
        print(f"Missing columns: {missing_cols}")
        # FAIL validation

    # Validate types
    type_requirements = {
        "id": "string",
        "timestamp": "string",  # ISO 8601
        "value": ["integer", "float"]  # Accept either
    }

    for col in schema['columns']:
        expected = type_requirements.get(col['name'])
        if expected and col['type'] not in (expected if isinstance(expected, list) else [expected]):
            print(f"Type mismatch: {col['name']} is {col['type']}, expected {expected}")
            # WARN or FAIL
    ```

    **Step 4: Data sample check**

    ```python
    data = preview_data(url=url, max_rows=20)

    # Check for null values in required fields
    for row in data['rows']:
        if not all(row.get(col) for col in required_columns):
            print("Null values in required columns")
            # FAIL validation

    # Check value ranges
    values = [row['value'] for row in data['rows']]
    if any(v < 0 for v in values):
        print("Negative values found (may be invalid)")
    ```

    **Step 5: Download test**

    ```python
    import requests
    response = requests.head(url, timeout=10)
    if response.status_code != 200:
        print(f"Download URL inaccessible: {response.status_code}")
        # FAIL validation
    ```

    **Step 6: Validation decision**

    Checklist for production approval:
    - [ ] All required metadata present
    - [ ] Quality score ≥70
    - [ ] Schema matches requirements
    - [ ] Data types correct
    - [ ] No null values in required fields
    - [ ] Value ranges valid
    - [ ] Download URL accessible

    **Cross-references:**
    - [Quality Metrics Guide](/guides/quality-metrics) - Quality thresholds
    - [Data Preview Guide](/guides/data-preview) - Schema and data validation
  </Tab>
</Tabs>

## Iterative exploration pattern

**Goal:** Discover datasets through progressive refinement

**When to use:** Unfamiliar domain, exploratory research, broad topic

**Pattern:**

1. **Broad search:** Start with semantic search, no filters
2. **Facet analysis:** Review facets (themes, formats, publishers) in results
3. **Refine:** Add relevant filters based on facets
4. **Related datasets:** Use find_related_datasets on promising results
5. **Quality filter:** Apply boost_quality once topic narrowed
6. **Deep dive:** Analyze top 3-5 candidates with quality and preview tools

**Example progression:**

```
Search 1: "umweltdaten" → 500 results
  ↓ (Review facets: ENVI theme dominant, CSV/JSON formats)
Search 2: themes=["ENVI"], formats=["CSV"] → 150 results
  ↓ (Find related to top result)
Search 3: Related to bev-stat-wien-2024 → 25 similar datasets
  ↓ (Apply quality filter)
Search 4: Same criteria + boost_quality → 10 high-quality results
  ↓ (Analyze finalists)
```

- [Searching Guide](/guides/searching) - Faceted search
- [Quality Metrics Guide](/guides/quality-metrics) - Related datasets

## Comparative analysis pattern

**Goal:** Compare multiple datasets for same topic

**When to use:** Choosing between alternatives, benchmarking, data fusion

**Pattern:**

1. Search for topic with multiple results
2. Analyze quality scores for all candidates
3. Preview schemas to compare structure
4. Find related datasets to expand options
5. Create comparison matrix
6. Select based on quality, recency, completeness

**Comparison matrix template:**

| Dataset | Quality | Columns | Last update | Format | License |
|---------|---------|---------|-------------|--------|---------|
| Bevölkerung Wien 2020-2024 | 87 | 15 | 2024-01 | CSV | CC-BY |
| Wien Einwohner nach Bezirk | 72 | 12 | 2023-06 | JSON | ODbL |
| Bundesweite Demografie 2023 | 65 | 18 | 2024-03 | CSV | CC0 |

**Decision criteria:**
- Research: Highest quality + recency
- Production: Quality + schema match + format
- Exploration: Most complete data (column count)

## Troubleshooting patterns

### Pattern fails at search step

**Symptom:** No relevant results from initial search

**Solutions:**
- Use semantic_search_datasets for query expansion
- Try German keywords if data is Austria-specific
- Search without filters first, then refine
- Check autocomplete_suggestions for theme and publisher IDs

### Pattern fails at quality check

**Symptom:** All candidates below quality threshold

**Solutions:**
- Lower threshold (research 85→70, production 70→60)
- Review quality breakdown for acceptable gaps
- Prioritize completeness over timeliness if metadata sparse
- Consider manual verification for niche domains

### Pattern fails at schema validation

**Symptom:** Required columns missing from all candidates

**Solutions:**
- Review column names in preview (may have different naming)
- Check if data structure differs from expectations
- Find related datasets with different schemas
- Contact publisher if critical data expected but missing
