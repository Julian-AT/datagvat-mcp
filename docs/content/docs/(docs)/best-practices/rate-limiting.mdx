Learn how to work within API rate limits and handle throttling errors effectively.

## Rate Limit Overview

data.gv.at MCP Server implements rate limiting to ensure fair API access and system stability:

**Limits:**
- **Sustained rate:** 10 requests/second
- **Burst capacity:** 20 requests (short-term spike allowance)
- **Window:** 1-second sliding window

**How it works:**
- You can burst up to 20 requests immediately
- After that, the rate drops to 10 req/s sustained
- Exceeding the limit returns a `429 Too Many Requests` error
- The system tracks requests per client connection

**Example scenario:**
```
Time 0-1s: Send 20 requests → All succeed (burst capacity)
Time 1-2s: Send 20 requests → 10 succeed, 10 rate-limited
Time 2-3s: Send 10 requests → All succeed (within sustained rate)
```

## Error Response Format

When rate limited, tools return a structured error:

```json
{
  "error": "Rate limit exceeded",
  "retry_after": 1.5,
  "limit": 10,
  "window": "1s",
  "remaining": 0
}
```

**Fields explained:**
- `error`: Human-readable error message
- `retry_after`: Seconds to wait before retrying (float)
- `limit`: Request limit per window
- `window`: Time window for rate limit
- `remaining`: Requests remaining in current window

**In tool responses:**

All data.gv.at MCP Server tools wrap errors in `ToolError` exceptions:

```python
try:
  results = search_datasets(query="health", limit=100)
except ToolError as e:
  if "Rate limit exceeded" in str(e):
    print("Hit rate limit, waiting before retry...")
    time.sleep(2)
```

## Automatic Retry Behavior

data.gv.at MCP Server includes **automatic retry middleware** that handles transient failures:

**Retry configuration:**
- **Attempts:** 3 total attempts (initial + 2 retries)
- **Backoff:** Exponential (1s → 2s → 4s → ...)
- **Max delay:** 60 seconds
- **Jitter:** Random delay variation to prevent thundering herd

**What gets retried automatically:**
- Rate limit errors (429)
- Temporary server errors (503)
- Network timeouts
- Connection errors

**What does NOT get retried:**
- Invalid parameters (400)
- Authentication errors (401, 403)
- Not found errors (404)
- Permanent server errors (500)

**Example timeline:**
```
0.0s: Request 1 → Rate limited (429)
1.2s: Request 1 retry → Rate limited (429)
3.5s: Request 1 retry → Success (200)
```

**User experience:**

You don't see rate limit errors unless:
1. Sustained high request rate (exceeding 10 req/s for >3 attempts)
2. Burst far exceeding capacity (>60 requests in short time)

The middleware handles temporary spikes automatically.

## Avoiding Rate Limits

### Strategy 1: Batch Operations Efficiently

Group related operations to minimize request count:

```python
# Bad: Inefficient: One request per dataset (30 requests)
dataset_ids = ["ds1", "ds2", ..., "ds30"]
for dataset_id in dataset_ids:
  dataset = get_dataset(dataset_id=dataset_id)
  process(dataset)

# Good: Efficient: Batch with delays (4 requests)
def fetch_in_batches(dataset_ids, batch_size=10):
  """Fetch datasets in batches to avoid rate limits."""
  results = []

  for i in range(0, len(dataset_ids), batch_size):
    batch = dataset_ids[i:i + batch_size]

    # Fetch batch in parallel (within 1s window)
    batch_results = [
      get_dataset(dataset_id=id)
      for id in batch
    ]

    results.extend(batch_results)

    # Wait 1 second between batches
    if i + batch_size < len(dataset_ids):
      time.sleep(1.0)

  return results

# Fetch 30 datasets in 3 batches (3s total)
datasets = fetch_in_batches(dataset_ids, batch_size=10)
```

**Performance:**
- Inefficient approach: ~30s (1 req/s with retries)
- Batch approach: ~3s (10 req/s sustained)

### Strategy 2: Use Pagination Wisely

Fetch larger pages instead of many small requests:

```python
# Bad: Inefficient: Many small pages (10 requests)
all_results = []
for page in range(10):
  page_results = search_datasets(
    query="health",
    limit=10,
    offset=page * 10
  )
  all_results.extend(page_results['results'])

# Good: Efficient: One large page (1 request)
results = search_datasets(
  query="health",
  limit=100  # Max page size
)
all_results = results['results']
```

**Tradeoff:**
- Smaller pages: Lower latency per request, more total requests
- Larger pages: Higher latency per request, fewer total requests
- **Recommended:** Use `limit=100` for batch operations, `limit=20` for interactive use

### Strategy 3: Cache Frequent Queries

Avoid repeated requests for same data:

```python
from datetime import datetime, timedelta
from functools import lru_cache

# Simple in-memory cache
metadata_cache = {}
cache_times = {}
CACHE_TTL = timedelta(minutes=15)

def get_dataset_cached(dataset_id):
  """Get dataset with 15-minute cache."""
  now = datetime.now()

  # Check cache
  if dataset_id in metadata_cache:
    cached_time = cache_times[dataset_id]
    if now - cached_time < CACHE_TTL:
      return metadata_cache[dataset_id]

  # Cache miss or expired - fetch fresh
  dataset = get_dataset(dataset_id=dataset_id)
  metadata_cache[dataset_id] = dataset
  cache_times[dataset_id] = now

  return dataset

# Usage
dataset = get_dataset_cached("vienna-health-2024")
# Subsequent calls within 15 minutes return cached data
```

**Impact:**
- 0 API calls for cached data
- Eliminates rate limit risk for repeated access
- See [Caching Strategies](/best-practices/caching-strategies) for advanced patterns

### Strategy 4: Implement Request Queuing

For sustained high-volume scenarios, use a request queue:

```python
import time
from queue import Queue
from threading import Thread

class RateLimitedClient:
  """Client with built-in rate limiting."""

  def __init__(self, requests_per_second=9):
    self.rate = requests_per_second
    self.interval = 1.0 / requests_per_second
    self.last_request = 0
    self.queue = Queue()
    self._start_worker()

  def _start_worker(self):
    """Background thread to process queue."""
    def worker():
      while True:
        func, args, kwargs = self.queue.get()

        # Throttle to target rate
        elapsed = time.time() - self.last_request
        if elapsed < self.interval:
          time.sleep(self.interval - elapsed)

        # Execute request
        result = func(*args, **kwargs)
        self.last_request = time.time()
        self.queue.task_done()

    thread = Thread(target=worker, daemon=True)
    thread.start()

  def enqueue(self, func, *args, **kwargs):
    """Add request to queue."""
    self.queue.put((func, args, kwargs))

  def wait(self):
    """Wait for all requests to complete."""
    self.queue.join()

# Usage
client = RateLimitedClient(requests_per_second=9)

dataset_ids = ["ds1", "ds2", ..., "ds100"]
for dataset_id in dataset_ids:
  client.enqueue(get_dataset, dataset_id=dataset_id)

# Wait for all to complete
client.wait()
```

**Benefits:**
- Never exceeds rate limit
- Smooth request distribution
- Predictable performance

**When to use:**
- Batch processing (>100 requests)
- Background jobs
- Data synchronization

## Detecting Rate Limit Errors

### Pattern Matching on Error Messages

Identify rate limit errors programmatically:

```python
def is_rate_limit_error(error):
  """Check if error is rate limit related."""
  error_msg = str(error).lower()
  rate_limit_indicators = [
    "rate limit exceeded",
    "too many requests",
    "429",
    "throttled"
  ]
  return any(indicator in error_msg for indicator in rate_limit_indicators)

# Usage
try:
  results = search_datasets(query="health", limit=100)
except ToolError as e:
  if is_rate_limit_error(e):
    print("Rate limited - implement backoff strategy")
  else:
    print(f"Other error: {e}")
```

### Exponential Backoff Implementation

For operations beyond automatic retry:

```python
import time
import random

def fetch_with_backoff(func, max_retries=5, base_delay=1.0):
  """Execute function with exponential backoff on rate limit."""

  for attempt in range(max_retries):
    try:
      return func()
    except ToolError as e:
      if not is_rate_limit_error(e):
        raise  # Not rate limit, re-raise

      if attempt == max_retries - 1:
        raise  # Max retries reached

      # Calculate delay with exponential backoff + jitter
      delay = base_delay * (2 ** attempt)
      jitter = random.uniform(0, 0.1 * delay)
      total_delay = min(delay + jitter, 60.0)  # Max 60s

      print(f"Rate limited, waiting {total_delay:.1f}s (attempt {attempt + 1}/{max_retries})")
      time.sleep(total_delay)

  raise RuntimeError("Max retries exceeded")

# Usage
def search_operation():
  return search_datasets(query="health", limit=100)

results = fetch_with_backoff(search_operation, max_retries=5)
```

**Backoff schedule:**
- Attempt 1: Wait 1s
- Attempt 2: Wait 2s
- Attempt 3: Wait 4s
- Attempt 4: Wait 8s
- Attempt 5: Wait 16s

## Custom Retry Strategy

When to implement beyond automatic retries:

### Use Case 1: Batch Processing with Progress Tracking

Track progress through large operations:

```python
def batch_fetch_with_retry(dataset_ids, progress_callback=None):
  """Fetch datasets with progress tracking and retry."""
  results = []
  failed = []

  for i, dataset_id in enumerate(dataset_ids):
    try:
      dataset = fetch_with_backoff(
        lambda: get_dataset(dataset_id=dataset_id),
        max_retries=3
      )
      results.append(dataset)

      if progress_callback:
        progress_callback(i + 1, len(dataset_ids), "success")

    except Exception as e:
      failed.append((dataset_id, str(e)))

      if progress_callback:
        progress_callback(i + 1, len(dataset_ids), "failed")

  return results, failed

# Usage with progress
def show_progress(current, total, status):
  print(f"Progress: {current}/{total} ({status})")

datasets, failed = batch_fetch_with_retry(
  dataset_ids=["ds1", "ds2", ..., "ds100"],
  progress_callback=show_progress
)

print(f"Succeeded: {len(datasets)}, Failed: {len(failed)}")
```

### Use Case 2: Priority Queue for Mixed Workloads

Prioritize certain requests over others:

```python
from queue import PriorityQueue

class PriorityRateLimiter:
  """Rate limiter with priority queue."""

  def __init__(self, requests_per_second=9):
    self.queue = PriorityQueue()
    self.rate = requests_per_second
    # ... (similar implementation to RateLimitedClient)

  def enqueue(self, func, priority=5, *args, **kwargs):
    """Add request with priority (lower = higher priority)."""
    self.queue.put((priority, func, args, kwargs))

# Usage
limiter = PriorityRateLimiter(requests_per_second=9)

# High-priority requests (user-facing)
for id in user_requested_ids:
  limiter.enqueue(get_dataset, priority=1, dataset_id=id)

# Low-priority requests (background)
for id in background_ids:
  limiter.enqueue(get_dataset, priority=10, dataset_id=id)
```

### Use Case 3: Circuit Breaker Pattern

Stop sending requests after repeated failures:

```python
from datetime import datetime, timedelta

class CircuitBreaker:
  """Circuit breaker to prevent cascading failures."""

  def __init__(self, failure_threshold=5, timeout=60):
    self.failure_threshold = failure_threshold
    self.timeout = timeout
    self.failures = 0
    self.last_failure_time = None
    self.state = "closed"  # closed, open, half-open

  def call(self, func):
    """Execute function with circuit breaker."""
    if self.state == "open":
      # Check if timeout elapsed
      if datetime.now() - self.last_failure_time > timedelta(seconds=self.timeout):
        self.state = "half-open"
        print("Circuit breaker half-open, attempting request...")
      else:
        raise RuntimeError("Circuit breaker open, too many failures")

    try:
      result = func()
      # Success - reset failures
      if self.state == "half-open":
        self.state = "closed"
        print("Circuit breaker closed, recovered")
      self.failures = 0
      return result

    except ToolError as e:
      if is_rate_limit_error(e):
        self.failures += 1
        self.last_failure_time = datetime.now()

        if self.failures >= self.failure_threshold:
          self.state = "open"
          print(f"Circuit breaker open, {self.failures} consecutive failures")

      raise

# Usage
breaker = CircuitBreaker(failure_threshold=5, timeout=60)

for dataset_id in dataset_ids:
  try:
    dataset = breaker.call(
      lambda: get_dataset(dataset_id=dataset_id)
    )
    process(dataset)
  except RuntimeError:
    print("Circuit breaker open, pausing operations")
    break
```

### Local Rate Limit Simulation

Simulate rate limiting for development:

```python
import time
from functools import wraps

def simulate_rate_limit(requests_per_second=10):
  """Decorator to simulate rate limiting."""
  last_call = [0.0]  # Mutable for closure

  def decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
      # Enforce rate limit
      interval = 1.0 / requests_per_second
      elapsed = time.time() - last_call[0]

      if elapsed < interval:
        wait_time = interval - elapsed
        raise ToolError(f"Rate limit exceeded, retry after {wait_time:.2f}s")

      last_call[0] = time.time()
      return func(*args, **kwargs)

    return wrapper
  return decorator

# Apply to development environment
@simulate_rate_limit(requests_per_second=10)
def search_datasets_dev(query, **kwargs):
  """Development version with rate limit simulation."""
  return search_datasets(query=query, **kwargs)
```

## Best Practices Summary

**DO:**
- Use batch operations (10 requests per second sustained)
- Cache frequently accessed data (15-minute TTL recommended)
- Fetch larger pages instead of many small requests
- Implement exponential backoff for sustained operations
- Monitor rate limit errors in production

**DON'T:**
- Don't poll at high frequency (>10 req/s)
- Don't bypass automatic retry (it's optimized)
- Don't fetch same data repeatedly (use caching)
- Don't ignore rate limit errors (implement backoff)
- Don't use small page sizes for batch operations

**Performance targets:**
- Single request: &lt;500ms (no rate limit)
- Burst (20 requests): &lt;2s
- Sustained (100 requests): ~10s (10 req/s)
- Cached request: &lt;10ms
