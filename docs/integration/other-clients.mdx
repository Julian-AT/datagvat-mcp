# Other MCP Clients

Austria MCP works with any MCP 1.0-compatible client. This guide covers integration with popular alternatives to Claude Desktop.

## Supported Clients

Austria MCP is compatible with:

- **Claude Desktop** - Anthropic's official client ([Setup Guide](/integration/claude-desktop))
- **Continue** - VS Code extension for AI coding assistance
- **Cline** - Terminal-based MCP client
- **Custom MCP Clients** - Any client implementing MCP 1.0 spec

## Continue (VS Code Extension)

Continue is a VS Code extension that brings AI assistance directly into your editor.

### Installation

1. Install Continue from VS Code marketplace
2. Open Continue settings (`.continue/config.json`)
3. Add Austria MCP server configuration

### Configuration

```json
{
  "mcpServers": {
    "austria-data": {
      "command": "uv",
      "args": [
        "run",
        "--directory",
        "/absolute/path/to/datagvat-mcp/mcp",
        "python",
        "-m",
        "app.server"
      ],
      "transport": "stdio"
    }
  }
}
```

### Usage

In VS Code with Continue:

```
@austria-data search for population datasets
```

The `@austria-data` prefix tells Continue to use your Austria MCP server.

## Cline (Terminal Client)

Cline is a terminal-based MCP client for command-line workflows.

### Installation

```bash
npm install -g @modelcontextprotocol/cline
```

### Configuration

Create `~/.cline/config.json`:

```json
{
  "servers": {
    "austria-data": {
      "command": "python",
      "args": ["-m", "app.server"],
      "cwd": "/absolute/path/to/datagvat-mcp/mcp",
      "env": {
        "AUSTRIA_MCP_LOG_LEVEL": "INFO"
      }
    }
  }
}
```

### Usage

```bash
cline connect austria-data
> list_catalogues(limit=5)
```

## FastMCP Client Library

Austria MCP uses FastMCP for both server and client. Using the FastMCP client library simplifies custom integrations by abstracting protocol details and providing type-safe APIs.

### Installation

```bash
pip install fastmcp>=2.14.0
```

### In-Memory Client Pattern

For testing, embedded usage, or applications that need direct access without subprocess overhead:

```python
from fastmcp import FastMCP
from fastmcp.client import Client

# Import Austria MCP server instance
from app.server import mcp

async def use_austria_mcp():
    """Direct in-memory connection to Austria MCP server."""
    # Connect to server without subprocess
    async with Client(mcp) as client:
        # List available tools
        tools = await client.list_tools()
        print(f"Available tools: {[t.name for t in tools]}")

        # Call tool with type-safe arguments
        result = await client.call_tool(
            "search_datasets",
            arguments={"query": "population", "limit": 10}
        )

        print(result)

        # List resources
        resources = await client.list_resources()

        # Read resource
        dataset = await client.read_resource("piveau://dataset/abc-123")
```

**Benefits:**
- **No subprocess management** - Direct function calls
- **No stdio parsing** - Native Python objects
- **Type-safe tool calls** - Pydantic validation
- **10-100x faster** - No IPC overhead (ideal for testing)
- **Simplified debugging** - Single process, full stack traces

**Use cases:**
- Unit testing MCP tools
- Jupyter notebooks / data science workflows
- Embedded applications (desktop apps, CLI tools)
- Development and debugging

### Subprocess Client Pattern

For production use with process isolation:

```python
from fastmcp.client import SubprocessClient

async def use_austria_mcp_isolated():
    """Production pattern with process isolation."""
    client = SubprocessClient(
        command="uv",
        args=["run", "--directory", "/path/to/mcp", "python", "-m", "app.server"],
        env={
            "AUSTRIA_MCP_LOG_LEVEL": "INFO",
            "AUSTRIA_MCP_PIVEAU_API_KEY": "your-api-key"
        }
    )

    async with client:
        # Same API as in-memory client
        tools = await client.list_tools()

        result = await client.call_tool(
            "list_catalogues",
            arguments={"limit": 5}
        )

        print(result)
```

**Benefits:**
- **Process isolation** - Server crashes don't affect client
- **Resource limits** - OS-level memory/CPU constraints
- **Different Python versions** - Client and server can use different Python
- **Standard MCP protocol** - Compatible with any MCP server

**When to use:**
- Production deployments
- Long-running services
- Untrusted code isolation
- Cross-platform compatibility

### HTTP Client Pattern (SSE)

For web applications and remote access:

```python
from fastmcp.client import HTTPClient

async def use_austria_mcp_remote():
    """Web-based client using Server-Sent Events."""
    client = HTTPClient(url="http://localhost:8080/sse")

    async with client:
        # Same API as other clients
        result = await client.call_tool(
            "semantic_search_datasets",
            arguments={"natural_query": "health data from Vienna"}
        )

        print(result)
```

**Starting SSE server:**
```bash
# Development server with hot reload
fastmcp dev app.server:mcp --host 0.0.0.0 --port 8080

# Production server with uvicorn
uvicorn app.sse_server:app --host 0.0.0.0 --port 8080 --workers 4
```

**Benefits:**
- **Remote access** - Client and server on different machines
- **Multiple clients** - Many clients can connect to one server
- **Web browser support** - Use from JavaScript/TypeScript
- **Load balancing** - Scale with reverse proxies

**Use cases:**
- Web applications
- Distributed systems
- Multi-tenant deployments
- Browser-based tools

### Error Handling

FastMCP client automatically handles protocol errors:

```python
from fastmcp.client import Client
from fastmcp.exceptions import ToolError, ConnectionError, TimeoutError

async def robust_client():
    try:
        async with Client(mcp) as client:
            result = await client.call_tool(
                "search_datasets",
                arguments={"query": "population"}
            )
    except ToolError as e:
        # Tool execution failed (e.g., invalid params, API error)
        print(f"Tool error: {e.message}")
    except ConnectionError as e:
        # Server connection failed
        print(f"Connection error: {e}")
    except TimeoutError as e:
        # Request timed out
        print(f"Timeout: {e}")
```

**Error types:**
- `ToolError` - Tool execution failed (invalid parameters, API errors)
- `ConnectionError` - Cannot connect to server
- `TimeoutError` - Request exceeded timeout
- `ValidationError` - Client-side parameter validation failed

### Progress Tracking

Monitor long-running operations using progress callbacks:

```python
from fastmcp.client import Client

async def track_progress():
    async with Client(mcp) as client:
        # Register progress callback
        def on_progress(current: int, total: int, message: str):
            percent = (current / total) * 100
            print(f"[{percent:.0f}%] {message}")

        client.on_progress = on_progress

        # Long-running operation with progress updates
        result = await client.call_tool(
            "analyze_dataset_quality",
            arguments={"dataset_id": "abc-123"}
        )
```

**Output:**
```
[0%] Fetching dataset metadata...
[25%] Analyzing completeness...
[50%] Checking data accessibility...
[75%] Computing quality score...
[100%] Analysis complete
```

### Batch Operations

Execute multiple tool calls efficiently:

```python
import asyncio
from fastmcp.client import Client

async def batch_search():
    async with Client(mcp) as client:
        # Parallel tool calls
        results = await asyncio.gather(
            client.call_tool("search_datasets", {"query": "health"}),
            client.call_tool("search_datasets", {"query": "education"}),
            client.call_tool("search_datasets", {"query": "transport"}),
        )

        for query, result in zip(["health", "education", "transport"], results):
            print(f"{query}: {result['count']} datasets")
```

### Testing with FastMCP Client

FastMCP client is ideal for unit testing:

```python
import pytest
from fastmcp.client import Client
from app.server import mcp

@pytest.mark.asyncio
async def test_search_datasets():
    """Test dataset search functionality."""
    async with Client(mcp) as client:
        # Test basic search
        result = await client.call_tool(
            "search_datasets",
            arguments={"query": "population", "limit": 10}
        )

        assert result["count"] > 0
        assert len(result["results"]) <= 10
        assert all("title" in r for r in result["results"])

@pytest.mark.asyncio
async def test_tool_validation():
    """Test parameter validation."""
    async with Client(mcp) as client:
        # Invalid limit should raise ValidationError
        with pytest.raises(Exception) as exc_info:
            await client.call_tool(
                "search_datasets",
                arguments={"limit": -1}  # Invalid
            )

        assert "validation" in str(exc_info.value).lower()
```

### Client Configuration

Configure client behavior:

```python
from fastmcp.client import SubprocessClient

client = SubprocessClient(
    command="python",
    args=["-m", "app.server"],
    cwd="/path/to/mcp",
    timeout=60.0,  # Request timeout in seconds
    env={
        "AUSTRIA_MCP_LOG_LEVEL": "DEBUG",
        "AUSTRIA_MCP_REQUEST_TIMEOUT": "30",

    # Capture server logs
    capture_stderr=True,

async with client:
    # Access server logs
    if client.stderr:
        logs = await client.stderr.read()
        print(logs)
```

## Custom MCP Clients

To integrate Austria MCP with your own MCP client:

### MCP Protocol Requirements

Your client must implement:

1. **stdio Transport** - Communicate via stdin/stdout
2. **JSON-RPC 2.0** - Message format
3. **MCP 1.0 Messages** - Initialize, tools/call, resources/list, etc.

### Connection Flow

```python
import subprocess
import json

# 1. Start Austria MCP server
process = subprocess.Popen(
    ["python", "-m", "app.server"],
    cwd="/path/to/mcp",
    stdin=subprocess.PIPE,
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    text=True
)

# 2. Send initialize request
initialize_request = {
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
        "protocolVersion": "1.0",
        "clientInfo": {
            "name": "my-client",
            "version": "1.0.0"
        }
    }
}

process.stdin.write(json.dumps(initialize_request) + "\n")
process.stdin.flush()

# 3. Read initialize response
response = json.loads(process.stdout.readline())

# 4. Send tools/call request
tool_request = {
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/call",
    "params": {
        "name": "list_catalogues",
        "arguments": {"limit": 5}
    }
}

process.stdin.write(json.dumps(tool_request) + "\n")
process.stdin.flush()

# 5. Read tool response
result = json.loads(process.stdout.readline())
print(result["result"])
```

## Transport Options

### stdio (Default)

Default transport using standard input/output:

```json
{
  "command": "python",
  "args": ["-m", "app.server"],
  "transport": "stdio"
}
```

**Pros:**
- Simple, widely supported
- No network configuration needed
- Works across all platforms

**Cons:**
- Single process communication only
- No remote access

### SSE (Server-Sent Events)

For web-based or remote clients:

```bash
# Start server with SSE transport
uvicorn app.sse_server:app --host 0.0.0.0 --port 8080
```

Client configuration:

```json
{
  "transport": "sse",
  "url": "http://localhost:8080/sse"
}
```

**Pros:**
- Supports remote clients
- Multiple concurrent connections
- Web browser compatibility

**Cons:**
- Requires network setup
- Additional security considerations

## Troubleshooting

### Client Can't Find Server

**Symptom:** Connection timeout or "command not found"

**Solutions:**
- Use absolute paths in configuration
- Verify Python is in PATH
- Check working directory is correct

### Tools Not Visible

**Symptom:** Client connects but shows no tools

**Solutions:**
- Ensure initialize handshake completed
- Check client implements tools/list method
- Verify MCP protocol version compatibility

### Performance Issues

**Symptom:** Slow responses or timeouts

**Solutions:**
- Increase request timeout in client config
- Check network latency (if using SSE)
- Monitor server logs for bottlenecks
