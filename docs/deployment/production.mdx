# Production Deployment

Best practices for deploying data.gv.at MCP Server server in production environments.

## Deployment Options

### Option 1: Local Deployment

Run data.gv.at MCP Server on each client machine:

**Pros:**
- Simple setup
- No network latency
- Isolated per user

**Cons:**
- Duplicate installations
- No centralized monitoring
- Updates required per machine

**Best for:** Individual users, development teams

### Option 2: Centralized Server

Run data.gv.at MCP Server as a service with SSE transport:

**Pros:**
- Centralized management
- Easy updates
- Shared monitoring

**Cons:**
- Network dependency
- Single point of failure
- Requires infrastructure

**Best for:** Organizations, multi-user deployments

### Option 3: Container Deployment

Deploy data.gv.at MCP Server in Docker containers:

**Pros:**
- Reproducible builds
- Easy scaling
- Platform independent

**Cons:**
- Container orchestration needed
- More complex setup

**Best for:** Cloud deployments, large organizations

## Environment Configuration

### Production Settings

```bash
# .env.production
AUSTRIA_MCP_LOG_LEVEL=WARNING
AUSTRIA_MCP_LOG_FORMAT=json
AUSTRIA_MCP_REQUEST_TIMEOUT=60
AUSTRIA_MCP_DEV_MODE=false
AUSTRIA_MCP_AUDIT_ENABLED=true
```

### Systemd Service (Linux)

Create `/etc/systemd/system/austria-mcp.service`:

```ini
[Unit]
Description=data.gv.at MCP Server Server
After=network.target

[Service]
Type=simple
User=austria-mcp
WorkingDirectory=/opt/austria-mcp/mcp
Environment="PATH=/opt/austria-mcp/venv/bin"
ExecStart=/opt/austria-mcp/venv/bin/python -m app.server
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

Enable and start:

```bash
sudo systemctl enable austria-mcp
sudo systemctl start austria-mcp
sudo systemctl status austria-mcp
```

### Docker Deployment

Create `Dockerfile`:

```dockerfile
FROM python:3.11-slim

WORKDIR /app

# Install dependencies
COPY mcp/pyproject.toml mcp/README.md ./
RUN pip install -e .

# Copy application
COPY mcp/app ./app

# Run server
CMD ["python", "-m", "app.server"]
```

Build and run:

```bash
docker build -t austria-mcp:latest .
docker run -d --name austria-mcp \
  --restart=always \
  -e AUSTRIA_MCP_LOG_LEVEL=WARNING \
  austria-mcp:latest
```

### Docker Compose

Create `docker-compose.yml`:

```yaml
version: '3.8'

services:
  austria-mcp:
    build: .
    container_name: austria-mcp
    restart: always
    environment:
      - AUSTRIA_MCP_LOG_LEVEL=WARNING
      - AUSTRIA_MCP_LOG_FORMAT=json
    volumes:
      - ./logs:/app/logs
    healthcheck:
      test: ["CMD", "python", "-c", "import app.server"]
      interval: 30s
      timeout: 10s
      retries: 3
```

## Disaster Recovery

### Backup Strategy

**What to backup:**
- Configuration files (`.env`, `config.json`)
- Custom middleware implementations
- API keys and credentials (encrypted)

**What NOT to backup:**
- Cache data (regenerated)
- Log files (use log aggregation instead)
- Temporary files

### Recovery Procedures

**Service failure:**

```bash
# Check status
systemctl status austria-mcp

# View logs
journalctl -u austria-mcp -n 100

# Restart service
systemctl restart austria-mcp
```

**Complete system failure:**

1. Restore configuration from backup
2. Reinstall dependencies
3. Start service
4. Verify functionality
5. Monitor for issues
