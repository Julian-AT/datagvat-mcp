# Testing

Learn how to write fast, deterministic tests for MCP servers using Austria MCP's proven testing patterns.

## Introduction

Testing MCP tools is critical because they involve:
- Distributed systems (client ↔ server ↔ API)
- External dependencies (Piveau API)
- User-facing errors (shown to Claude)
- Async operations (Context, HTTP clients)

Austria MCP's testing approach:
- **Fast feedback:** Unit tests run in <1s, no subprocess overhead
- **Isolation:** Mock external dependencies (PiveauClient, APIs)
- **Determinism:** No network calls, no time-based flakiness
- **Coverage:** Test happy path + error cases + edge cases

## Testing Philosophy

### Test Pyramid

```
        /\
       /E2E\      ← Few: Full integration (optional)
      /------\
     /Integ  \    ← Some: In-memory FastMCP client
    /----------\
   /  Unit Tests \ ← Many: Mock Context, fast execution
  /--------------\
```

**Unit tests (majority):**
- Test individual tools in isolation
- Mock PiveauClient responses
- Fast execution (<1s for entire suite)

**Integration tests (selective):**
- Test tool registration and discovery
- Verify middleware stack behavior
- Use in-memory Client (no subprocess)

**E2E tests (optional):**
- Test with real Piveau API (if needed)
- Slow, reserved for critical flows

## Mock Context Pattern

The core pattern for testing MCP tools: mock FastMCP's Context to provide app state.

### Creating Mock Context

From `mcp/tests/conftest.py`:

```python
from unittest.mock import AsyncMock, MagicMock
from fastmcp import Context
from app.client import PiveauClient
from app.config import Settings
from app.server import AppState

def create_mock_context(
    settings: Settings | None = None,
    client: AsyncMock | None = None,
) -> MagicMock:
    """Create mock Context with app state."""
    # Default settings if not provided
    if settings is None:
        settings = Settings(
            piveau_api_base="https://test.api.at",
            piveau_api_key="test-key",
        )

    # Default mock client if not provided
    if client is None:
        client = AsyncMock(spec=PiveauClient)

    # Create app state (lifespan context)
    app_state = AppState(
        settings=settings,
        piveau_client=client
    )

    # Create mock Context
    ctx = MagicMock(spec=Context)
    ctx.request_context = MagicMock()
    ctx.request_context.lifespan_context = app_state
    ctx.report_progress = AsyncMock()
    ctx.request_id = "test-request-123"

    return ctx
```

### Why This Pattern?

- **Context provides app state:** Tools access `ctx.request_context.lifespan_context`
- **Mock allows controlling responses:** Set `client.search.return_value`
- **AsyncMock for async methods:** `ctx.report_progress` is async

### Using Mock Context in Tests

From `mcp/tests/test_tools.py`:

```python
async def test_list_catalogues_success(sample_catalogues_list):
    # Arrange: Mock client response
    mock_client = AsyncMock(spec=PiveauClient)
    mock_client.list_catalogues.return_value = sample_catalogues_list

    ctx = create_mock_context(client=mock_client)

    # Act: Call tool
    from app.tools.discovery import register_discovery_tools
    mcp = FastMCP("test")
    register_discovery_tools(mcp)

    tools = mcp._tool_manager._tools
    list_catalogues = tools["list_catalogues"].fn
    result = await list_catalogues(ctx, limit=100, offset=0, value_type="metadata")

    # Assert: Verify result
    assert len(result) == 2
    mock_client.list_catalogues.assert_called_once_with(
        limit=100, offset=0, value_type=ValueType.METADATA
    )
```

## Testing Tools (Unit Tests)

### Pattern 1: Happy Path

Test successful tool execution:

```python
async def test_search_datasets_success():
    """Test search returns results correctly."""
    # Arrange: Mock the client response
    mock_client = AsyncMock(spec=PiveauClient)
    mock_client.search_datasets_advanced.return_value = {
        "results": [{"id": "ds-1", "title": "Dataset 1"}],
        "count": 1,
        "facets": {}
    }

    ctx = create_mock_context(client=mock_client)

    # Act: Call tool
    from app.tools.discovery import register_discovery_tools
    mcp = FastMCP("test")
    register_discovery_tools(mcp)

    search_datasets = mcp._tool_manager._tools["search_datasets"].fn
    result = await search_datasets(ctx, query="population", limit=10)

    # Assert: Verify result structure
    assert result["count"] == 1
    assert len(result["results"]) == 1
    assert "facets" in result

    # Assert: Verify client was called correctly
    mock_client.search_datasets_advanced.assert_called_once()
```

### Pattern 2: Error Handling

Test tool converts exceptions to ToolError:

```python
from fastmcp.exceptions import ToolError
import pytest

async def test_search_handles_api_error():
    """Test tool handles API errors gracefully."""
    # Arrange: Mock raises exception
    mock_client = AsyncMock(spec=PiveauClient)
    mock_client.search_datasets_advanced.side_effect = httpx.HTTPStatusError(
        message="Not found",
        request=Mock(),
        response=Mock(status_code=404)
    )

    ctx = create_mock_context(client=mock_client)

    # Act + Assert: Expect ToolError
    from app.tools.discovery import register_discovery_tools
    mcp = FastMCP("test")
    register_discovery_tools(mcp)

    search_datasets = mcp._tool_manager._tools["search_datasets"].fn

    with pytest.raises(ToolError, match="API error"):
        await search_datasets(ctx, query="bad")
```

### Pattern 3: Validation

Test input validation:

```python
async def test_search_validates_limit():
    """Test tool validates limit parameter."""
    ctx = create_mock_context()

    from app.tools.discovery import register_discovery_tools
    mcp = FastMCP("test")
    register_discovery_tools(mcp)

    search_datasets = mcp._tool_manager._tools["search_datasets"].fn

    # Limit too high
    with pytest.raises(ToolError, match="limit must be between"):
        await search_datasets(ctx, query="test", limit=2000)

    # Limit too low
    with pytest.raises(ToolError, match="limit must be between"):
        await search_datasets(ctx, query="test", limit=0)
```

### Pattern 4: Progress Reporting

Test Context usage:

```python
async def test_list_catalogues_reports_progress():
    """Test tool reports progress via Context."""
    mock_client = AsyncMock(spec=PiveauClient)
    mock_client.list_catalogues.return_value = [{"id": "cat-1"}]

    ctx = create_mock_context(client=mock_client)

    from app.tools.discovery import register_discovery_tools
    mcp = FastMCP("test")
    register_discovery_tools(mcp)

    list_catalogues = mcp._tool_manager._tools["list_catalogues"].fn
    await list_catalogues(ctx, limit=100, offset=0, value_type="metadata")

    # Assert: Progress was reported
    assert ctx.report_progress.call_count >= 1
```

## Testing Middleware

### Pattern: Middleware Isolation

Test middleware independently from tools:

```python
from app.middleware import AuditMiddleware
from fastmcp.server.middleware import MiddlewareContext
import logging

async def test_audit_middleware_logs_timing(caplog):
    """Test AuditMiddleware logs execution time."""
    # Arrange: Create middleware and mock context
    middleware = AuditMiddleware()
    ctx = MagicMock(spec=MiddlewareContext)
    ctx.fastmcp_context = MagicMock()
    ctx.fastmcp_context.request_id = "test-123"
    ctx.arguments = {"name": "test_tool"}

    async def mock_handler(context):
        """Simulate tool execution."""
        await asyncio.sleep(0.01)  # Simulate work
        return {"result": "success"}

    # Act: Call middleware
    with caplog.at_level(logging.INFO):
        result = await middleware.on_call_tool(ctx, mock_handler)

    # Assert: Verify result passed through
    assert result == {"result": "success"}

    # Assert: Verify timing logged
    assert any("ms" in record.message for record in caplog.records)
    assert any("completed" in record.message for record in caplog.records)
```

### Testing Auth Middleware

From `mcp/tests/test_middleware.py`:

```python
from app.middleware import AuthMiddleware

async def test_auth_middleware_allows_read_tools():
    """Test AuthMiddleware allows read operations without API key."""
    middleware = AuthMiddleware()

    # Mock context without API key
    ctx = create_middleware_context(
        tool_name="list_catalogues",
        has_api_key=False
    )

    call_next = AsyncMock(return_value="result")

    # Should not raise (read tool)
    result = await middleware.on_call_tool(ctx, call_next)
    assert result == "result"

async def test_auth_middleware_blocks_write_tools():
    """Test AuthMiddleware requires API key for write operations."""
    middleware = AuthMiddleware()

    # Mock context without API key
    ctx = create_middleware_context(
        tool_name="create_dataset_draft",
        has_api_key=False
    )

    call_next = AsyncMock()

    # Should raise ToolError
    with pytest.raises(ToolError, match="API key required"):
        await middleware.on_call_tool(ctx, call_next)
```

### Testing Error Propagation

```python
async def test_audit_middleware_reraises_exceptions():
    """Test AuditMiddleware logs but re-raises exceptions."""
    middleware = AuditMiddleware()
    ctx = create_middleware_context(tool_name="failing_tool")

    call_next = AsyncMock(side_effect=ValueError("Test error"))

    with pytest.raises(ValueError, match="Test error"):
        await middleware.on_call_tool(ctx, call_next)
```

## Integration Testing with In-Memory Client

FastMCP provides in-memory testing without subprocess overhead.

### Creating Test Server

From `mcp/tests/conftest.py`:

```python
from fastmcp import FastMCP
import pytest

@pytest.fixture
def mcp_server() -> FastMCP:
    """Create FastMCP instance with all tools registered."""
    from app.tools.discovery import register_discovery_tools
    from app.tools.analysis import register_analysis_tools
    from app.tools.management import register_management_tools
    from app.tools.vocabularies import register_vocabulary_tools
    from app.resources import register_resources
    from app.prompts import register_prompts

    mcp = FastMCP(
        name="austria-data-test",
        instructions="Test server for Austria Open Data",
    )

    # Register all tools
    register_discovery_tools(mcp)
    register_analysis_tools(mcp)
    register_management_tools(mcp)
    register_vocabulary_tools(mcp)
    register_resources(mcp)
    register_prompts(mcp)

    return mcp
```

### Testing Tool Discovery

```python
from fastmcp.client import Client

async def test_integration_list_tools(mcp_server):
    """Test full tool discovery flow."""
    async with Client(mcp_server) as client:
        tools = await client.list_tools()

        # Verify all tools registered
        tool_names = [t.name for t in tools]
        assert "list_catalogues" in tool_names
        assert "search_datasets" in tool_names
        assert "get_dataset" in tool_names

        # Verify tool count
        assert len(tool_names) >= 20
```

### Testing End-to-End Tool Call

```python
async def test_integration_search_flow(mcp_server):
    """Test search from client through middleware to tool."""
    # Note: This requires mocking PiveauClient in server state
    # for true integration test without real API calls

    async with Client(mcp_server) as client:
        result = await client.call_tool(
            "search_datasets",
            arguments={"query": "health", "limit": 5}
        )

        # Verify response structure
        assert "results" in result
        assert "count" in result
        assert "facets" in result
```

### When to Use Integration Tests

**Use integration tests for:**
- Verify tool registration works correctly
- Test middleware stack behavior
- Validate full request/response flow
- Check tool schema generation

**Don't use integration tests for:**
- Testing tool logic (use unit tests)
- Testing individual error cases (use unit tests)
- Testing external APIs (mock them)

## Testing Best Practices

### DO

✅ **Mock external dependencies:**
```python
mock_client = AsyncMock(spec=PiveauClient)
mock_client.search.return_value = {...}
```

✅ **Test both success and failure paths:**
```python
async def test_success(): ...
async def test_handles_404_error(): ...
async def test_handles_timeout(): ...
```

✅ **Use descriptive test names:**
```python
# Good
async def test_search_returns_empty_when_no_results(): ...

# Bad
async def test_search(): ...
```

✅ **Test error messages:**
```python
with pytest.raises(ToolError, match="limit must be between"):
    await search_datasets(ctx, limit=2000)
```

✅ **Use fixtures for common setup:**
```python
@pytest.fixture
def mock_context(test_settings):
    return create_mock_context(settings=test_settings)
```

✅ **Run tests frequently during development:**
```bash
# Watch mode (with pytest-watch)
ptw -- -v
```

### DON'T

❌ **Don't use subprocess for testing:**
```python
# Bad - slow, flaky
subprocess.run(["python", "-m", "app.server"])
```

❌ **Don't make real network calls:**
```python
# Bad - non-deterministic
response = await httpx.get("https://real-api.com")
```

❌ **Don't test FastMCP framework itself:**
```python
# Bad - trust the framework
def test_fastmcp_context_injection(): ...
```

❌ **Don't skip error cases:**
```python
# Bad - most bugs are in error handling
async def test_only_happy_path(): ...
```

❌ **Don't use sleep() for timing:**
```python
# Bad - slow tests
await asyncio.sleep(1)
```

### Common Pitfalls

From 22-RESEARCH.md:

**Pitfall 1: Subprocess testing**
- Problem: Tests spawn subprocess, causing flaky tests and slow execution
- Solution: Use in-memory `Client(mcp_server)` instead

**Pitfall 2: Missing Context mocking**
- Problem: Tools crash because Context doesn't have app state
- Solution: Always use `create_mock_context()` fixture

**Pitfall 3: Wrong mock type**
- Problem: Using `MagicMock()` for async methods causes "not awaitable" errors
- Solution: Use `AsyncMock()` for async methods

## Debugging Test Failures

### Common Failures and Solutions

**AsyncMock not awaited:**
```python
# Problem
ctx.report_progress = MagicMock()  # Wrong!

# Solution
ctx.report_progress = AsyncMock()  # Correct
```

**Context missing app state:**
```python
# Problem
ctx = MagicMock(spec=Context)  # Missing lifespan_context

# Solution
ctx = create_mock_context()  # Includes app state
```

**Tests hang:**
```python
# Problem
async def test_something():  # Missing decorator
    await tool(ctx)

# Solution
@pytest.mark.asyncio  # Add this
async def test_something():
    await tool(ctx)
```

**Flaky tests:**
```python
# Problem
await httpx.get("https://real-api.com")  # Real network call

# Solution
mock_client.get.return_value = {...}  # Mock it
```
